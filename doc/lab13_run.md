# ЛР13: TF-IDF

Реализована схема **lnc.ltc** из `lesson-09. Текстовое ранжирование.pdf`:
логарифмический TF документов без IDF, логарифмический TF × IDF запроса,
косинусная нормировка обоих векторов. Основные структуры, накопление оценок
и ограниченная куча top-k написаны на C++ без STL-контейнеров.

## Нормы документов

```powershell
New-Item -ItemType Directory -Force data/tfidf | Out-Null
build/boolean-native/tfidf_index.exe build --index data/boolean/lab7_2026-11-07/index --positions data/positions/lab10_2026-11-07/positions --output data/tfidf/new_lab13 --reserve-mib 4608
```

Build читает **исходные несжатые** индексы ЛР7/ЛР10, предварительно проверяет
все их контрольные суммы и структуру. Все координаты одного термина группируются
по документу; TF равен числу координат в заголовке и тексте вместе. Совпадения
по разным полям учитываются отдельно. DF сверяется с булевым индексом.
Исходный корпус, MongoDB и архив HTML не нужны.

Норма — квадратный корень из суммы квадратов `1+log10(tf)` **по всем терминам**
выбранного пространства. У лемм отдельные нормы; каждая альтернатива — своя ось.
Поэтому нормы нельзя вычислять по словоформам и применять к леммам или считать
только по словам запроса. IDF берётся из DF булева индекса, N включает пустые документы.

Выходной каталог должен быть новым. При прерывании остаётся `INCOMPLETE`;
такой каталог не открывается. Резерв — 4608 МиБ плюс размер выхода.
Готовый файл: `data/tfidf/lab13_2026-11-08/norms.bin`, 7 661 408 байт.
Заголовок 80 байт: magic/version, N, V, привязка к индексу, размер,
FNV-64 содержимого, версия формулы, число пространств, резервные поля.
Далее идут два массива норм IEEE binary64 little-endian, сначала surface, затем lemma.
Пустой документ имеет нулевую норму. Привязка включает заголовки `terms.bin`,
`documents.bin`, `position_terms.bin` с исключением поля, меняющегося при pack.
Один файл норм подходит к исходному и соответствующему упакованному индексу.

```powershell
build/boolean-native/tfidf_index.exe verify --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --norms data/tfidf/lab13_2026-11-08
```

Проверка привязки, размеров, FNV и конечности всех норм выполняется также
при открытии поиска. `verify` не пересчитывает нормы из координат;
численную правильность формулы проверяет независимый эталон GoogleTest.

## CLI и веб-форма

```powershell
build/boolean-native/boolean_search.exe --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --ranking tfidf --norms data/tfidf/lab13_2026-11-08 --query 'doom eternal' --limit 10
```

Без `--query`: одна строка UTF-8 в stdin → один ответ JSONL в stdout.
Леммы: `--space lemma --dict data/lemmas/ru_en_v1/dictionary.bin`.

- `--ranking boolean` — прежний язык AND/OR/NOT и фразы, порядок по ID;
  это режим по умолчанию.
- `--ranking tfidf` — обычный текст, модель мешка слов. Операторы считаются
  словами, кавычки не задают фразу. Каждый известный термин запроса — отдельная
  ось; повторы увеличивают query TF, общие альтернативы лемм объединяются
  с суммированием частот. Неизвестные термины исключаются из вектора запроса.
- Рассматриваются документы хотя бы с одним термином ненулевого веса.
  Если `df=N`, IDF равен нулю. Запрос без известных терминов или только из
  терминов с нулевым IDF возвращает пустой ответ. Запрос без токенов — ошибка.
- Результаты: `score` по убыванию, при точном равенстве — исходный uint64 ID
  по возрастанию. `total` — число документов с положительной оценкой,
  `--limit 0..1000` ограничивает только вывод. Максимум 64 токена запроса
  и 512 различных терминов после раскрытия лемм.
- В ответе также есть `weighting`, `query_terms`, `decoded_coordinates`.
  Оценка — мера сходства, не вероятность релевантности.

```powershell
python serve_search.py --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --dict data/lemmas/ru_en_v1/dictionary.bin --norms data/tfidf/lab13_2026-11-08
```

Открыть <http://127.0.0.1:8080/> и выбрать TF-IDF. Веб-форма вызывает то же
C++-ядро и показывает числовые оценки. Время из ответа исключает открытие
индекса, чтение/проверку норм и загрузку словаря; полный HTTP-запрос включает их.

## Замеры и оценка

```powershell
python run_lab13.py
```

Семь раундов в двух пространствах: OR с порядком по ID и TF-IDF для
сравнения времени на одинаковом наборе кандидатов. Отдельный булев запрос
AND даёт первые результаты для оценки релевантности; его число совпадений
не приравнивается к числу результатов TF-IDF.
В каждом процессе сначала прогревочный пакет, затем измеряемый; порядок режимов
и запросов чередуется. Кэш ОС не сбрасывается. Сохраняются все 196 измерений,
выдачи, медианы, SHA-256 бинарника, словаря, норм и упакованного индекса.
Для этих запросов отдельно проверяется равенство числа кандидатов OR и TF-IDF,
для повторений — неизменность top-10 и оценок.

`tests/fixtures/lab13_title_judgments.json` содержит явную разметку объединения
top-5 AND/ID и TF-IDF для трёх запросов по названиям игр.
Её выполнил помощник по **заголовкам**:
1 — заголовок прямо называет искомую игру, 0 — тема из заголовка не установлена.
Скрипт считает P@5, проверяя также совпадение сохранённых заголовков.
Это иллюстративная оценка видимого соответствия теме на малой выборке;
полные тексты не размечались, общая релевантность корпуса не оценивалась.

## Ограничения

На запрос читаются координаты его терминов, а оценки накапливаются в массиве
из N double. Две нормы на документ требуют 16N байт, оценки — ещё 8N;
на этом корпусе суммарно 11,49 МБ плюс словарь, буферы и top-k.
Обход массива оценок — O(N), куча занимает O(k), отбор — O(M log k),
где M — число документов с положительной оценкой. Для частых слов дорого
читать все координаты; следующий шаг — хранить TF прямо в постингах.
Нормировка не устраняет преимущества очень коротких текстов, зоны не взвешены,
контекст неоднозначных лемм не учитывается. Точные фразы и булевы ограничения
пока доступны только в отдельном булевом режиме.
