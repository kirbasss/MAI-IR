# Лабораторная работа №2: запуск робота

Требуются Python 3.11+ и MongoDB, доступная по адресу из секции `db` в
`crawler.example.yaml`. Для локального запуска MongoDB откройте Docker Desktop
и выполните из корня проекта:

```powershell
docker compose up -d
docker compose ps
```

Если раньше был запущен контейнер `mai-ir-mongo` отдельной командой
`docker run`, сначала остановите его командой `docker stop mai-ir-mongo`,
иначе порт 27017 будет занят. Compose использует тот же именованный том
`mai-ir-mongo`, поэтому сохранённые данные останутся доступными.

С активированной `.venv` запустите робота:

```powershell
python -m pip install -r requirements.txt
python crawler.py crawler.example.yaml
```

Тесты запускаются отдельно (для них нужны дополнительные зависимости):

```powershell
python -m pip install -r requirements-dev.txt
python run_tests.py
```

Остановить сервис можно командой `docker compose down`: именованный том при
этом сохраняется. Команду `docker compose down -v` не используйте, если хотите
сохранить базу данных.

Основной аргумент `crawler.py` — путь к YAML. Флаг `--seed-only` добавляет
URL в очередь без сетевой загрузки HTML. Относительный путь
`logic.inventory` отсчитывается от расположения этого YAML. Пример конфигурации
обрабатывает не более 10 страниц за запуск из `urls.txt`. Следующий запуск
возьмёт оставшиеся URL. Полный инвентарь расположен в
`data/discovery/inventory_all/url_inventory.tsv`; он получается командой
`merge-inventories` и не хранится в Git.

Пошаговая подготовка к пакетной и большой обкачке, а также обновлению
sitemap, описана в `doc/lab2_large_crawl.md`. `crawler.large.yaml` уже
указывает на полный инвентарь; его запуск добавит весь миллион URL в очередь.
Сначала оцените расход места на выборке с `crawler.batch.yaml`.

В MongoDB создаются четыре коллекции: `frontier` (очередь и состояние),
`raw_pages` (нормализованный URL, источник, Unix timestamp загрузки и сырой
HTML), `documents` (результат разбора и ссылка `raw_page_id` на сырой HTML),
`crawler_meta` (импорт инвентаря и паузы для сайтов). Ключ `_id` в первых
трёх коллекциях — нормализованный URL. В `documents.fetched_at` хранится
время последнего изменения HTML, в `frontier.last_checked_at` — время
последней проверки. Состояние `in_progress`, оставшееся после аварийной
остановки, возвращается в начало очереди при следующем запуске.
Одновременно должен работать только один экземпляр робота с этой базой.

Старую базу, в которой HTML ещё встроен в `documents`, нужно перенести до
следующей обкачки. Сначала создайте резервную копию MongoDB, затем проверьте
предпросмотр и выполните идемпотентный перенос:

```powershell
python migrate_raw_pages.py crawler.example.yaml
python migrate_raw_pages.py crawler.example.yaml --apply
python crawler_status.py crawler.example.yaml
```

`--apply` сначала сохраняет и проверяет HTML в `raw_pages`, только затем
удаляет его из `documents`. Повторный запуск безопасен. В `playground-1.mongodb.js`
есть только читающие запросы для демонстрации структуры и состояния базы.

При `logic.run_forever: false` программа завершится, когда нет доступных
сейчас URL. Для непрерывной проверки поставьте `run_forever: true` и уберите
`max_documents`; интервал ожидания задаётся `poll_seconds`.

Исходные HTML/JSON из ЛР1 и данные MongoDB в репозиторий не добавляются.
Автотесты робота используют имитацию MongoDB и HTTP; поэтому они не требуют
сетевого доступа или запущенного сервера. Для полного прогона с настоящим
сервером достаточно запустить приведённый пример на небольшой выборке.
