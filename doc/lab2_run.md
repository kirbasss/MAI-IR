# Лабораторная работа №2: запуск робота

Требуются Python 3.11+ и MongoDB, доступная по адресу из секции `db` в
`crawler.example.yaml`. Для локального запуска можно использовать MongoDB
Community Server или Docker. Docker Desktop нужно запустить заранее:

```powershell
docker run -d --name mai-ir-mongo -p 127.0.0.1:27017:27017 -v mai-ir-mongo:/data/db mongo:8.0
```

Из корня проекта:

```powershell
python -m pip install -r requirements-dev.txt
python crawler.py crawler.example.yaml
python run_tests.py
```

Единственный аргумент `crawler.py` — путь к YAML. Относительный путь
`logic.inventory` отсчитывается от расположения этого YAML. Пример конфигурации
обрабатывает не более 10 страниц за запуск из `urls.txt`. Следующий запуск
возьмёт оставшиеся URL. Для крупного обхода укажите
`data/discovery/inventory_all/url_inventory.tsv`; этот локальный инвентарь
получается командой `merge-inventories` и не хранится в Git.

В MongoDB создаются три коллекции: `frontier` (очередь и состояние),
`documents` (сырой HTML, разбор и время загрузки), `crawler_meta` (признак
завершённого импорта инвентаря). Ключ `_id` в первых двух коллекциях —
нормализованный URL. В `documents.fetched_at` хранится Unix timestamp
последнего изменения HTML, в `frontier.last_checked_at` — время последней
проверки. Состояние `in_progress`, оставшееся после аварийной остановки,
возвращается в начало очереди при следующем запуске. Одновременно должен
работать только один экземпляр робота с этой базой.

При `logic.run_forever: false` программа завершится, когда нет доступных
сейчас URL. Для непрерывной проверки поставьте `run_forever: true` и уберите
`max_documents`; интервал ожидания задаётся `poll_seconds`.

Исходные HTML/JSON из ЛР1 и данные MongoDB в репозиторий не добавляются.
Автотесты робота используют имитацию MongoDB и HTTP; поэтому они не требуют
сетевого доступа или запущенного сервера. Для полного прогона с настоящим
сервером достаточно запустить приведённый пример на небольшой выборке.
