# Лабораторная работа №2: запуск робота

Требуются Python 3.11+ и MongoDB, доступная по адресу из секции `db` в
`crawler.example.yaml`. Для локального запуска MongoDB откройте Docker Desktop
и выполните из корня проекта:

```powershell
docker compose up -d
docker compose ps
```

Если раньше был запущен контейнер `mai-ir-mongo` отдельной командой
`docker run`, сначала остановите его командой `docker stop mai-ir-mongo`,
иначе порт 27017 будет занят. Compose использует тот же именованный том
`mai-ir-mongo`, поэтому сохранённые данные останутся доступными.

С активированной `.venv` запустите робота:

```powershell
python -m pip install -r requirements.txt
python crawler.py crawler.example.yaml
```

Обычный запуск сначала проверяет актуальные `robots.txt` и корневые sitemap
источников из `logic.sitemap_sources`, обновляет дочерние карты при необходимости,
объединяет найденные URL с сохранёнными и добавляет
отсутствующие адреса в MongoDB `frontier`. Затем берёт новые задания и повторы
их временных ошибок. Предварительная команда `discover` не нужна: если
`logic.inventory` ещё не существует, робот создаст его сам. Для отдельной
проверки уже обработанных страниц запустите после наступления интервала:

```powershell
python revisit.py crawler.example.yaml
python crawler_status.py crawler.example.yaml
```

`revisit.py` использует тот же YAML, но не импортирует инвентарь и не берёт
новые URL. Он проверяет только задания, для которых наступило время
`frontier.available_at` (в том числе прежние `gone` и `blocked`). Первую
проверку назначает `logic.revisit_seconds` после загрузки; если страница не
изменилась, следующая назначается через тот же интервал после проверки.
По умолчанию это 2 592 000 секунд, то есть 30 суток. Повторный запуск команды
до срока не делает лишних запросов.

Тесты запускаются отдельно (для них нужны дополнительные зависимости):

```powershell
python -m pip install -r requirements-dev.txt
python run_tests.py
```

Остановить сервис можно командой `docker compose down`: именованный том при
этом сохраняется. Команду `docker compose down -v` не используйте, если хотите
сохранить базу данных.

Основной аргумент `crawler.py` — путь к YAML. Флаг `--seed-only` добавляет
URL в очередь без загрузки HTML-публикаций, но с сетевой загрузкой robots и
sitemap при `refresh_sitemaps: true`. Относительный путь
`logic.inventory` отсчитывается от расположения этого YAML. Пример конфигурации
обновляет карты StopGame и обрабатывает не более 10 заданий за запуск.
В очередь при этом попадают все найденные адреса, а не только десять.
Следующий запуск возьмёт оставшиеся URL. Полный инвентарь восьми сайтов
расположен в `data/discovery/inventory_all/url_inventory.tsv`; теперь его
создаёт и обновляет сам робот с `crawler.large.yaml`. Инвентарь не хранится в Git.

При `run_forever: true` карты повторно проверяются через
`sitemap_refresh_interval_seconds` после окончания предыдущего обновления,
даже если очередь пуста. При каждом новом обычном запуске обновление выполняется
сразу. `crawler.batch.yaml` явно отключает его (`refresh_sitemaps: false`): это
специальный режим фиксированной выборки, для которого TSV должен уже существовать.

Корневые карты проверяются по сети при каждом цикле. Дочерние карты используют
кеш XML и отдельный `.http.json` с ETag, Last-Modified, временем HTTP-проверки,
хешем тела и `lastmod` из родительского индекса. Новая карта или изменение
`lastmod` вызывает запрос сразу. При неизменном известном `lastmod` локальная
копия используется не дольше `sitemap_recheck_seconds` (сутки). Для карт без
этой подсказки действует `sitemap_cache_ttl_seconds` (час); 0 отключает пропуск
HTTP-запросов к дочерним картам. Это допускает до часа задержки обнаружения
изменений в существующей карте, если сайт не сообщает её `lastmod`.
Свежие ранее скачанные XML без `.http.json` принимаются с тем же коротким TTL,
после проверки корректности XML. Повторное чтение кеша не продлевает TTL.

При HTTP-проверке используются `If-None-Match` / `If-Modified-Since`; ответ 304
позволяет использовать сохранённое тело. Неполный или повреждённый кеш требует
полного ответа; 304 без кеша повторяется без условных заголовков. Сбой и капча
не заменяют рабочую копию. Правила robots и общие задержки не обходятся.
Полный сетевой цикл при необходимости (при остановленном роботе):

```powershell
python refresh_inventory.py crawler.large.yaml --force
```

В логах и `crawler_meta.sitemap_refresh` отдельно видны запросы карт,
локальные попадания кеша и ответы 304. Число новых URL считается как разность
множеств нормализованных адресов, а не как изменение общего числа строк.
Удаление старых каталогов/дубликатов не скрывает новые публикации; рабочие
старые URL, исчезнувшие из свежей sitemap, по-прежнему сохраняются.

HTTP-запросы к robots, sitemap и публикациям используют общий механизм задержек:

- `global_delay_seconds` — минимальная пауза после завершения любого запроса;
- `local_delay_seconds` — минимальная пауза между запросами к одному сайту;
- `source_delays_seconds` — локальные переопределения по именам источников;
- `Crawl-delay` из `robots.txt` — дополнительное нижнее ограничение для хоста.

Ограничения не складываются: запрос ждёт, пока разрешат все соответствующие
таймеры. Время разбора HTML уже входит в прошедшее время ожидания; если оно
заняло всю необходимую паузу, дополнительной задержки не будет. Старый ключ
`delay_seconds` поддерживается как запасное имя для `local_delay_seconds`.

Пошаговая подготовка к пакетной и большой обкачке, а также обновлению
sitemap, описана в `doc/lab2_large_crawl.md`. `crawler.large.yaml` уже
указывает на полный инвентарь; его запуск добавит весь миллион URL в очередь.
Сначала оцените расход места на выборке с `crawler.batch.yaml`.

В MongoDB создаются четыре коллекции: `frontier` (очередь и состояние),
`raw_pages` (нормализованный URL, источник, Unix timestamp загрузки и сырой
HTML), `documents` (результат разбора и ссылка `raw_page_id` на сырой HTML),
`crawler_meta` (импорт инвентаря, обновление sitemap и паузы для сайтов). Ключ `_id` в первых
трёх коллекциях — нормализованный URL. В `documents.fetched_at` хранится
время последнего изменения HTML, в `frontier.last_checked_at` — время
последней проверки. Состояние `in_progress`, оставшееся после аварийной
остановки, возвращается в начало очереди при следующем запуске.
Одновременно должен работать только один экземпляр робота с этой базой.
Прерванная или временно неудачная повторная проверка остаётся за `revisit.py`,
а не переходит к обычной загрузке. При `304` или совпадении SHA-256
сохранённые HTML и разбор не перезаписываются; изменившийся HTML сохраняется
в `raw_pages`, заново разбирается и обновляется в `documents`.

Известные страницы-каталоги Eurogamer, PC Gamer и GamingOnLinux не
импортируются из инвентаря; редирект публикации на каталог получает статус
`excluded`. Уже сохранённые страницы можно переклассифицировать и заново
разобрать из `raw_pages` без сетевой загрузки. Сначала выполните предпросмотр,
затем, при остановленном краулере, примените изменения:

```powershell
python repair_saved_documents.py crawler.batch.yaml
python repair_saved_documents.py crawler.batch.yaml --apply
```

Команда не удаляет HTML. У исключённых страниц выставляется
`documents.indexable: false`, а фотографии и видео без прозы получают
`parsed.metadata.content_kind: media_only` и остаются доступными для
будущего поиска по заголовку. Галереи PC Gamer разбираются по подписям
слайдов без дублирования одинакового текста.

Фильтры также исключают страницы авторов Eurogamer, авторов, тегов и архивов
PC Gamer, проверенные рубрики с пагинацией, списки игр StopGame
`/games/compilation/` и перенаправления на главную. Обычные статьи с похожими
словами в URL не исключаются. Парсер IXBT при отсутствии HTML-блока может
извлечь текст из `props.publication.blocks[].html` встроенного JSON только
для текущей страницы, без текстов рекомендаций. Старые видео GameMAG с
`<object>` тоже считаются медиаматериалами.

Перед парсингом робот распознаёт известные признаки CAPTCHA/антибот-страницы:
характерный заголовок, форму проверки, виджет либо короткое сообщение
проверки человека без текста публикации. Такие ответы, включая HTTP 200,
получают `retry` с `last_error: anti_bot_or_challenge`; весь источник ставится
на паузу до следующей попытки. Пустой или пробельный ответ HTTP 200 получает
`retry` с `last_error: empty_response`. Они не перезаписывают сохранённые
HTML и разбор. HTTP 502/504, как и остальные 5xx, также включают паузу сайта;
`Retry-After` учитывается при назначении повтора. При блокировке sitemap
действуют те же правила, а старый инвентарь остаётся доступен.

Распознавание эвристическое: незнакомую заглушку оно может пропустить.
Робот не решает CAPTCHA, не запускает браузер и не обходит блокировки.
Само слово «captcha» в тексте статьи или JavaScript не означает блокировку.
Команда исправления выше возвращает ранее сохранённые пустые ответы и
распознанные заглушки из `done` в `retry`, убирая условные HTTP-заголовки,
но сохраняя исходный HTML как свидетельство. `documents_requeued` показывает
число таких задач. Обычная ошибка парсера остаётся в
`documents.parsed.parse_error`, не превращаясь автоматически в сетевой `retry`.

Старую базу, в которой HTML ещё встроен в `documents`, нужно перенести до
следующей обкачки. Сначала создайте резервную копию MongoDB, затем проверьте
предпросмотр и выполните идемпотентный перенос:

```powershell
python migrate_raw_pages.py crawler.example.yaml
python migrate_raw_pages.py crawler.example.yaml --apply
python crawler_status.py crawler.example.yaml
```

`--apply` сначала сохраняет и проверяет HTML в `raw_pages`, только затем
удаляет его из `documents`. Повторный запуск безопасен. В `playground-1.mongodb.js`
есть только читающие запросы для демонстрации структуры и состояния базы.

При `logic.run_forever: false` каждая команда завершится, когда в её режиме
нет доступных сейчас URL. `max_documents` ограничивает число URL за один
запуск любой команды. Для непрерывной работы выбранного режима поставьте
`run_forever: true` и уберите `max_documents`; интервал ожидания задаётся
`poll_seconds`. В `crawler_status.py` поля `new_due_now` и `revisit_due_now`
показывают количество заданий, доступных соответствующей команде (без учёта
временных пауз для сайтов).

Исходные HTML/JSON из ЛР1 и данные MongoDB в репозиторий не добавляются.
Автотесты робота используют имитацию MongoDB и HTTP; поэтому они не требуют
сетевого доступа или запущенного сервера. Для полного прогона с настоящим
сервером достаточно запустить приведённый пример на небольшой выборке.

Результат обновления карт записывается в `crawler_meta` с `_id: "sitemap_refresh"`
и выводится `crawler_status.py`: статус `ok`, `partial` или `failed`, количество
найденных и новых URL, ошибки источников и время следующего обновления.
Сбой отдельного сайта не удаляет его старые URL и не мешает другим сайтам.
При полном сбое робот продолжит по старому inventory; если его ещё нет,
завершится с ошибкой вместо создания пустой очереди. Ранее обработанные URL
не переводятся обратно в `pending`: их обновлением по-прежнему занимается `revisit.py`.
