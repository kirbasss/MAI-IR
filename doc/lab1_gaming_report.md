**Курс:** «Информационный поиск»

## Задание

## Корпус и источники

Один документ корпуса — отдельная редакционная публикация: новость, статья,
обзор, превью или аналитический материал. В финальном корпусе будут
использованы по меньшей мере два независимых источника. На старте выбраны:

| Код | Источник | Адрес | Планируемые классы |
|---|---|---|---|
| `playground` | PlayGround.ru | <https://www.playground.ru/> | новости, мнения/обзоры |
| `stopgame` | StopGame.ru | <https://stopgame.ru/> | новости, статьи, обзоры |
| `ixbt_games` | IXBT.games | <https://ixbt.games/> | новости, статьи, обзоры |
| `igromania` | Игромания | <https://www.igromania.ru/> | новости, статьи, обзоры |

В `urls.txt` внесено 15 репрезентативных страниц: 3 PlayGround, 5 StopGame,
4 IXBT.games и 3 Игромании. В выборке есть новости, статьи и обзоры;
массовый обход на этом этапе намеренно не запускается.

## Метод сбора и формат хранения

Программа запускается так:

```powershell
python main.py collect urls.txt --delay 2
```

Перед первым запросом к источнику она получает `robots.txt`, сохраняет его и
проверяет URL для собственного User-Agent. Запрещённый URL не скачивается.
Ответы классифицируются как обычная страница, редирект, 404, 429, 5xx,
anti-bot/challenge или запрет `robots.txt`; диагностическая JSON-запись
создаётся и при ошибке. CAPTCHA и WAF не обходятся.

Сырой HTML хранится в `data/raw/<source>/`, результат разбора — в
`data/parsed/<source>/`. В JSON также записывается путь к исходному HTML,
поэтому его можно повторно разобрать без сети командой `python main.py reparse`.

Все источники приводятся к модели:

```json
{
  "source": "stopgame",
  "url": "https://...",
  "title": "...",
  "author": "...",
  "published_at": "...",
  "category": "news",
  "tags": [],
  "games": [],
  "text": "...",
  "metadata": {},
  "parse_error": null,
  "http_status": 200,
  "raw_size_bytes": 203473,
  "text_size_bytes": 2144,
  "text_sha256": "..."
}
```

Не найденные на странице значения не заполняются догадками. URL
канонизируются только в части tracking-параметров (`utm_*`, `fbclid`,
`gclid`, `yclid`); содержательные параметры сохраняются.

## Robots.txt и доступность

Перед каждой загрузкой сохранены актуальные `robots.txt` и диагностические
файлы `data/discovery/<source>/robots_status.json`. У всех четырёх источников
`robots.txt` получен с HTTP 200, и каждый из 15 URL разрешён User-Agent
проекта. В дальнейшем эти правила надо загружать заново перед каждым
запуском, а не считать сохранённый снимок постоянным разрешением на обход.

## Разметка документов и выделение текста

Все правила ниже проверены на сохранённых HTML: по 3 страницам PlayGround и
Игромании, 4 IXBT.games и 5 StopGame. В каждом случае найден ровно один
контейнер основного текста; после разбора он даёт не менее 100 слов.

| Источник | Основной текст | Заголовок и служебные поля | Категория и таксономия |
|---|---|---|---|
| PlayGround | `div.article-content` | `h1`, JSON-LD `headline`, `author`, `datePublished` | URL `/<игра>/news/` → `news`, `.../opinion/` → `review`; JSON-LD `about.name` → `games` |
| StopGame | `article#material_content` | `h1`, JSON-LD/Open Graph | `newsdata` → `news`; `show` с «обзор» в заголовке → `review`; `a[class*='_tag_']` → `tags`, `a.game-link[data-gamelink-game]` → `games` |
| IXBT.games | `div[id^="publication-"].prose` | `h1`, JSON-LD `headline`, `author`, `datePublished` | JSON-LD `articleSection`: «Новости», «Статьи», «Обзоры» → `news`, `article`, `review` |
| Игромания | `div[class*="material-content_"]` | `h1`, JSON-LD `headline`, `author`, `datePublished` | JSON-LD `@type`: `NewsArticle`, `Article`, `Review`; `div[class*="TagsOfArticle_tags"] a` → `tags` |

У PlayGround внешний `article` не используется: он включает карточку игры,
комментарии и рекомендации. В IXBT.games числовой суффикс ID динамический,
поэтому выбран устойчивый префикс `publication-` вместе с классом `prose`.
У Игромании суффикс CSS Modules также динамический, поэтому используется
совпадение по стабильному фрагменту класса. Теги Игромании дублируются в
desktop- и mobile-блоках, а HTML-сущности в JSON-LD PlayGround декодируются;
дубликаты отбрасываются.

На StopGame нельзя извлекать любой `article`: другие такие элементы содержат
комментарии и карточки рекомендаций. Внутри `#material_content` блоки с
`_read-more` («Предыдущий отчёт», «Подробнее по теме», «Читай также»)
удаляются до извлечения. IXBT.games не даёт на проверенных страницах
отдельных надёжных тегов или имён игр, поэтому эти поля намеренно остаются
пустыми, а не заполняются догадками.

## Существующий поиск

Корпус пригоден для следующих работ: публикации можно искать встроенными
средствами сайтов и внешними поисковиками с ограничением `site:`. Проверка
проведена 19 сентября 2026 года: для каждого кейса известен документ, который
должен быть найден, а первые результаты сохранены в `doc/img/`.

| Запрос и ожидаемый документ | Наблюдение | Вывод о недостатке |
|---|---|---|
| `джо кросс`: новости о Джозефе Кроссе на StopGame и Игромании | Встроенный поиск StopGame выдаёт материалы о «кроссовере» и «кросс-плее», а не о человеке. Яндекс с `site:stopgame.ru` не находит релевантную новость; для Игромании он показывает один релевантный документ. Google выдаёт релевантные публикации обоих сайтов в первых позициях. | Полнота и ранжирование заметно зависят от поисковой системы; собственный поиск StopGame плохо обрабатывает имя «Джо/Джозеф Кросс». |
| Фраза `приземлённый подход Insomniac` из статьи IXBT.games о Marvel's Wolverine | Внутренний поиск IXBT.games сообщает «Ничего не найдено», хотя фраза есть в сохранённой статье. Яндекс с `site:ixbt.games` находит эту статью первой. | Внутренний поиск не гарантирует поиск по полному тексту и не может служить единственным ориентиром полноты. |
| Цитата `я играю роль поп-звезды, которая убила себя на сцене` из блога StopGame «Музыка Ночного Города» | Встроенная выдача StopGame возвращает несвязанные блоги; Яндекс выводит нужный блог первым. | Даже точная фраза не даёт ожидаемого результата во внутреннем поиске; неизвестны используемые токенизация и ранжирование. |
| `леман` на StopGame | Первый результат — блог «Косплемания: Chummomo…». В статье искомая последовательность встречается только как часть слова «Косплемания», а не как отдельная сущность «Ле-Ман». | Поиск сопоставляет подстроки без границ слова и выдаёт тематически нерелевантный документ. |

В StopGame, напротив, есть вкладки типов документов и сортировка. | Внешние и часть встроенных поисков не используют заданные для корпуса поля `category`, `tags`, `games`; собственной системе нужны зонный поиск и фильтры. |

## План тестирования и результат

Автотесты запускаются командой:

```powershell
python -m unittest discover -s tests -v
```

Выполненный прогон: `Ran 5 tests ... OK`.

| Тест | Что проверяется | Статус |
|---|---|---|
| StopGame parser | правильный селектор, автор, основной текст, исключение связанных материалов, извлечение игры | пройден |
| Statistics | два закреплённых StopGame-fixture успешно считаются без дубликатов | пройден |
| URL canonicalisation | удаляются только tracking-параметры, `page=2` сохраняется | пройден |
| Все источники | 15 raw HTML повторно проходят парсеры с подтверждёнными селекторами, текстом >100 слов и нормализованной категорией | пройден |
| Таксономия | классы PlayGround и IXBT.games, теги Игромании и игры StopGame сохранены в ожидаемых полях | пройден |

Далее полезно добавить отдельные сохранённые ответы 404, 429, robots.txt и
challenge-страницы для проверки диагностических ветвей.

## Вывод и дальнейшие действия

Настроена воспроизводимая основа игрового корпуса: общий формат документа,
сохранение raw HTML, диагностика, повторный разбор без сети, статистика и
проверенные специализированные парсеры для четырёх независимых источников.
ЛР 1 по диагностической выборке выполнена. Перед сбором порядка миллиона
документов следующий шаг — отдельно оценить доступный объём sitemap/RSS и
разбить обход на уважительные, контролируемые партии.
