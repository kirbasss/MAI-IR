# Лабораторная работа № 1 — добыча корпуса документов

**Курс:** «Информационный поиск»  
**Тема корпуса:** русскоязычные публикации об играх и игровой индустрии  
**Дата среза:** 18 сентября 2026 г.

## Задание

Нужно скачать примеры документов будущего корпуса, изучить формат и
метаданные, выделить основной текст, найти существующие средства поиска и
посчитать характеристики выборки.

## Корпус и источники

Один документ корпуса — отдельная редакционная публикация: новость, статья,
обзор, превью или аналитический материал. В финальном корпусе будут
использованы по меньшей мере два независимых источника. На старте выбраны:

| Код | Источник | Адрес | Планируемые классы |
|---|---|---|---|
| `playground` | PlayGround.ru | <https://www.playground.ru/> | новости, мнения/обзоры |
| `stopgame` | StopGame.ru | <https://stopgame.ru/> | новости, статьи, обзоры |
| `ixbt_games` | IXBT.games | <https://ixbt.games/> | новости, статьи, обзоры |
| `igromania` | Игромания | <https://www.igromania.ru/> | новости, статьи, обзоры |

В `urls.txt` внесено по две репрезентативные страницы каждого источника:
короткая новость и более длинный материал там, где это возможно. Массовый
обход на этом этапе намеренно не запускается.

## Метод сбора и формат хранения

Программа запускается так:

```powershell
python main.py collect urls.txt --delay 2
```

Перед первым запросом к источнику она получает `robots.txt`, сохраняет его и
проверяет URL для собственного User-Agent. Запрещённый URL не скачивается.
Ответы классифицируются как обычная страница, редирект, 404, 429, 5xx,
anti-bot/challenge или запрет `robots.txt`; диагностическая JSON-запись
создаётся и при ошибке. CAPTCHA и WAF не обходятся.

Сырой HTML хранится в `data/gaming/raw/<source>/`, результат разбора — в
`data/gaming/parsed/<source>/`. Игровые данные вынесены в отдельный каталог,
поэтому не смешиваются с прежней темой lyrics.

Все источники приводятся к модели:

```json
{
  "source": "stopgame",
  "url": "https://...",
  "title": "...",
  "author": "...",
  "published_at": "...",
  "category": "news",
  "tags": [],
  "games": [],
  "text": "...",
  "metadata": {},
  "parse_error": null,
  "http_status": 200,
  "raw_size_bytes": 203473,
  "text_size_bytes": 2144,
  "text_sha256": "..."
}
```

Не найденные на странице значения не заполняются догадками. URL
канонизируются только в части tracking-параметров (`utm_*`, `fbclid`,
`gclid`, `yclid`); содержательные параметры сохраняются.

## Robots.txt и доступность

Актуальный `robots.txt` StopGame сохранён в
`data/gaming/discovery/stopgame/robots.txt`: для `User-agent: *` запрещены,
в частности, `/search`, `/admin`, `/pm` и личные страницы; путь `newsdata`
не запрещён. Поэтому две новости ниже допустимо было скачать обычным
HTTP-клиентом с собственным User-Agent.

Для PlayGround подтверждена публичная карта сайта
`https://www.playground.ru/sitemap.xml`; его правила запрещают служебные пути
вроде `/search/`, `/download/`, `/account/` и `/api/`, но не типовые
материалы вида `/<game>/opinion/...`. Для Игромании известны sitemap-index и
разделы `news`, `articles`, `reviews`; пути `/search/`, `/api/`, `/accounts/`
исключаются. Перед реальной загрузкой этих источников программа заново
сохранит именно текущие правила, а не будет доверять этому описанию.

## Разметка документов и выделение текста

### StopGame — проверено на локальных HTML-образцах

В обеих сохранённых страницах:

| Данные | Подтверждённое место |
|---|---|
| Основной текст | `article#material_content` |
| Заголовок | `h1`; дублируется в JSON-LD `NewsArticle.headline` |
| Автор | JSON-LD `NewsArticle.author.name`; также Open Graph `og:article:author:username` |
| Дата | JSON-LD `datePublished`; также `og:article:published_time` |
| Краткое описание | JSON-LD `description`, `meta[name=description]` |
| Упомянутые игры | ссылки `a.game-link[data-gamelink-game]` внутри основного текста |

Нельзя извлекать любой `article` на странице: для комментариев и карточек
рекомендаций используются другие элементы `article`. Внутри
`#material_content` блоки классов с фрагментом `_read-more` содержат ссылки
«Предыдущий отчёт», «Подробнее по теме», «Читай также»; они удаляются до
извлечения. Это проверяется автоматическим тестом.

### Остальные источники — статус проверки

Страницы PlayGround, IXBT.games и Игромании видны внешнему веб-поиску: на
них доступны заголовок, автор, дата, рубрика и полный текст публикации.
Однако в этой локальной среде соединение к их IP-адресам завершалось тайм-аутом
до HTTP-ответа, поэтому **сырые HTML-образцы этих трёх сайтов ещё не
зафиксированы и специфические CSS-селекторы не объявлены подтверждёнными**.
Это намеренное ограничение: нельзя подбирать селекторы «на глаз» или
подменять HTML текстом поисковой выдачи.

До появления их образцов код использует только консервативный семантический
резерв: `[itemprop=articleBody]`, `article`, затем `main`; он помечает JSON
полем `metadata.parser_mode = semantic_fallback_requires_fixture_validation`.
После сохранения 2–5 HTML-страниц каждого источника этот режим должен быть
заменён конкретными проверенными правилами.

## Существующий поиск

Корпус пригоден для последующих работ: документы индексируются внешним
веб-поиском, а у StopGame в интерфейсе есть поле поиска. Ниже приведены
проверенные запросы внешнего поиска с ограничением `site:`.

| Запрос | Наблюдение |
|---|---|
| `site:playground.ru/elden_ring/opinion "Обзор Elden Ring" "Поле чудес"` | Находится нужный обзор PlayGround. В выдаче рядом заметны данные карточки игры (жанры, оценка, дата), которые не являются основным текстом статьи. |
| `site:stopgame.ru/newsdata "BioShock 4" "ценник GTA VI"` | Находится сохранённый материал StopGame о квартальном отчёте Take-Two. В сниппете видны и связанные блоки «Предыдущий отчёт», поэтому собственному парсеру их нельзя бездумно индексировать. |
| `site:ixbt.games/news "GTA VI" "ПК"` | Находятся несколько близких новостей IXBT.games, в том числе материалы о релизе GTA VI на ПК. Это пример сильной тематической и свежестной конкуренции документов. |
| `site:igromania.ru/news "Второй трейлер GTA VI"` | Находится новость Игромании о 475 млн просмотров; видны рубрика «Индустрия», автор и теги `#индустрия`, `#игры`, `#GTA 6`. |

Недостатки такого поиска: его ранжирование ориентировано на свежесть и
популярность, не позволяет точно отделить основной текст от блоков страницы,
не гарантирует одинаковой полноты по всем сайтам и не даёт управлять
нормализацией русских слов, опечаток и названий игр. Именно это будет
проверочным ориентиром для собственной системы.

## План тестирования и результат

Автотесты запускаются командой:

```powershell
python -m unittest discover -s tests -v
```

Выполненный прогон: `Ran 3 tests ... OK`.

| Тест | Что проверяется | Статус |
|---|---|---|
| StopGame parser | правильный селектор, автор, основной текст, исключение связанных материалов, извлечение игры | пройден |
| Statistics | 2 документа, 2 успешных разбора, нет дубликатов | пройден |
| URL canonicalisation | удаляются только tracking-параметры, `page=2` сохраняется | пройден |

После получения образцов остальных сайтов план расширяется теми же тестами
для каждого подтверждённого селектора, плюс кейсами 404, 429, robots.txt и
challenge-страницы.

## Вывод и дальнейшие действия

Настроена воспроизводимая и безопасная основа игрового корпуса: общий формат
документа, сохранение сырого HTML, диагностика, точные дубликаты, статистика
и проверенный парсер StopGame.

Работа ещё не является финально завершённой ЛР 1: для требования о двух
источниках необходимо локально сохранить и проверить HTML минимум ещё одного
сайта, а для целевого масштаба — изучить sitemap/RSS и посчитать доступные
URL, не скачивая их массово. Следующий безопасный шаг — повторить
`python main.py collect urls.txt` в сети с доступом к всем четырём доменам,
сохранить 2–5 образцов каждого и только после ручной сверки включать их в
малую выборку 20–50 документов на источник.
