# ЛР10: цитатный поиск и координаты

`doom AND eternal` требует наличия обоих слов где угодно в документе.
`"doom eternal"` дополнительно требует соседних позиций и указанного порядка.
Для этого к индексу ЛР7 добавлены координаты каждого вхождения токена.
Исходные HTML и MongoDB при поиске не нужны.

## Семантика

- Кавычки `"..."` задают фразу. Она становится операндом прежнего булева языка:
  `"doom eternal" AND NOT quake`, `"god of war" OR "the witcher"`.
- Все слова фразы должны идти подряд в одном поле одного документа.
  Заголовок и основной текст имеют независимую нумерацию от нуля.
- Сравниваются нормализованные токены: регистр и пунктуация обрабатываются токенизатором.
  Это поиск последовательности слов, а не точное побайтовое совпадение текста.
  Например, `"DOOM, Eternal!"` и `"doom eternal"` эквивалентны.
- В режиме словоформ требуется совпадение словоформ; в режиме лемм допускаются
  различные формы, но сохраняются соседство и порядок. Обе стороны используют
  тот же словарь, что индекс. Неоднозначные леммы исходного слова имеют одну координату.
- Стоп-слова не удаляются. Повторные слова учитываются: `"red red"` требует двух позиций.
- Фраза не пересекает границу заголовка и текста. Границы предложений внутри поля
  отдельно не учитываются. Поиск с допустимым расстоянием (slop) пока не реализован.
- Кавычки должны быть парными; экранирование кавычек внутри фразы не поддерживается.
  Пустые фразы и фразы длиннее 64 токенов дают ошибку.

Без `--positions` обычные булевы запросы работают как в ЛР8,
а фразовый запрос возвращает явное сообщение об отсутствии координат.

## Сборка и тесты

Нативная Windows Release-сборка:

```bash
cmake -S . -B build/boolean-native -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_DEMO=OFF
cmake --build build/boolean-native --target positional_index boolean_search --parallel 2
```

Пересборка в Docker (Git Bash):

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps tokenizer-tests sh -ec 'cmake -S /src -B /build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build /build --parallel 2'
docker compose run --rm --no-deps tokenizer-tests phrase_search_tests --gtest_color=yes
```

В PowerShell убрать префикс `MSYS_NO_PATHCONV=1`. GoogleTest использует собственные
маленькие корпуса и словарь; скачивать данные для тестов не нужно.
Все проверки группы, включая CLI и Python-обвязку:

```bash
python run_tests.py --lab 10
```

Проверяются порядок и соседство, повторные слова и несколько вхождений,
границы полей, фразы в обоих пространствах, неизвестные слова, 64-битные ID,
пустой корпус, ошибки кавычек, UTF-8-передача из формы и обработка stdin.
Для 14 фраз из одного--трёх слов в каждом пространстве результат сравнивается
с независимой проверкой скользящим окном по восьми текстам.
Отдельный корпус вызывает более 24 частей и два прохода слияния:
результат побайтово сравнивается с построением при большем буфере.
Есть проверки контрольных сумм, усечения, незавершённого индекса,
несовпадающего корпуса, словаря и защиты существующего результата.

## Построение координат на настоящем корпусе

Нужен **тот же снимок**, по которому построен булев индекс.
Диск E с сырым HTML подключать не требуется. Готовый снимок:
`data/zipf/run_2026-11-07/snapshot/corpus.bin`.

Скрипт сначала запускает тесты, затем C++-построение, полную проверку,
три повторения каждого запроса из `tests/fixtures/lab10_queries.txt` и сохранение отчётных данных:

```bash
python run_lab10.py --index data/boolean/lab7_2026-11-07/index --corpus data/zipf/run_2026-11-07/snapshot/corpus.bin --dict data/lemmas/ru_en_v1/dictionary.bin --output data/positions/lab10_checks --report-dir doc/lab10
```

Выбрать **новый** каталог `--output`. Резерв свободного места по умолчанию — 4608 МиБ
(4,5 ГиБ); при достижении резерва запись прекращается с ошибкой.
Корпус и булев индекс не изменяются. Временные части удаляются после успешного
слияния; при ошибке частичные данные сохраняются с маркером `INCOMPLETE`.
Автоматическое продолжение прерванной сборки не реализовано.

Проверенный результат располагается в
`data/positions/lab10_2026-11-07/positions`.
Существующий булев индекс перестраивать не требуется.

## Демонстрация

CLI из Git Bash:

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps tokenizer-tests boolean_search --index /indexes/lab7_2026-11-07/index --positions /positions/lab10_2026-11-07/positions --query '"doom eternal"' --limit 5
MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps tokenizer-tests positional_index inspect --index /indexes/lab7_2026-11-07/index --positions /positions/lab10_2026-11-07/positions --term doom --limit 10
```

Вторая команда показывает ID документа, поле и номер токена для каждого
из первых вхождений. Общее число вхождений отличается от df — один документ
может содержать несколько координат слова. `--term` ожидает готовый
нормализованный токен; `--space lemma` выбирает координаты конкретной леммы.

Без `--query` поисковая утилита читает UTF-8-запросы из stdin, по одному в строке.
Формат JSONL, точный `total` и ограничение отображаемой выдачи сохранены из ЛР8.
Пример пакетного запуска в Git Bash:

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm -T --no-deps tokenizer-tests boolean_search --index /indexes/lab7_2026-11-07/index --positions /positions/lab10_2026-11-07/positions < tests/fixtures/lab10_queries.txt > build/lab10_demo.jsonl
```

Веб-форма после нативной сборки:

```bash
python serve_search.py --index data/boolean/lab7_2026-11-07/index --positions data/positions/lab10_2026-11-07/positions --dict data/lemmas/ru_en_v1/dictionary.bin
```

Открыть <http://127.0.0.1:8080/> и сравнить `doom AND eternal` с `"doom eternal"`.
Можно переключать словоформы/леммы, вводить несколько фраз и булевы операции.
Полная проверка готового расширения:

```bash
build/boolean-native/positional_index.exe verify --index data/boolean/lab7_2026-11-07/index --positions data/positions/lab10_2026-11-07/positions
```

## Структуры и алгоритм

Расширение написано на C++17 без STL-контейнеров. Собственная хеш-таблица
сопоставляет нормализованный термин его номеру в словаре ЛР7.
Формируются записи `(номер термина, порядковый номер документа, поле/позиция)`.
Собственная стабильная поразрядная сортировка использует два массива
с общим бюджетом `--memory-mib` (по умолчанию 64 МиБ).
Промежуточные части сливаются собственной минимальной кучей,
не более 24 входов за проход. Одинаковые координаты удаляются.

Файлы `position_terms.bin` и `positions.bin` имеют явное little-endian представление:

| Файл | Запись |
|---|---|
| `position_terms.bin` | Смещение в координатах и количество, два uint64 (16 байт) на термин ЛР7 |
| `positions.bin` | Порядковый номер документа uint32 и поле/позиция uint32 (8 байт) на вхождение |

Второе число содержит бит поля и 31-битный номер токена. Порядковый номер
документа переводится в исходный ID через таблицу ЛР7; поэтому ID могут быть
произвольными uint64. Формат поддерживает до 2^32−1 документов и не более 2^32−2 терминов,
до 2^31 позиций в поле. Эти пределы проверяются при построении.
Для обхода пределов потребуется новая версия формата.

80-байтные заголовки содержат число записей, длину и FNV-64 payload,
отпечаток заголовков четырёх файлов базового индекса, корпуса и словаря.
Исходный корпус проверяется по ID, количеству документов и полному FNV-64
потока байтов. Чужое расширение и незавершённые файлы отвергаются.
Проверка `verify` сверяет суммы, границы списков, принадлежность документов,
порядок и отсутствие повторных координат.

Для фразы из `m` токенов поток координат слова с номером `i` сдвигается на `−i`.
Пересечение сдвинутых потоков даёт начало фразы: совпадать должны документ,
поле и начальная позиция. Потоки разных лемм одного слова сначала объединяются.
Поддерживается не более 512 потоков на фразу. Списки координат и полная
выдача не загружаются целиком в память. ID каждого найденного документа
выдаётся один раз, даже при нескольких вхождениях фразы.

Поиск сохраняет порядок по ID. Ранжирования, сниппетов, сжатия и прыжков
по спискам в этой работе нет. Рост числа совпадений в режиме лемм
не является измерением релевантности.
