# ЛР12: ускорение и прыжки по индексу

ЛР12 продолжает сжатый индекс ЛР11. Постинги и координаты VB не переписываются:
отдельное расширение хранит контрольные точки для переходов вперёд.
Исходный корпус, MongoDB и HTML для работы не нужны.

## Сборка и проверки

```powershell
cmake -S . -B build/boolean-native -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_DEMO=OFF
cmake --build build/boolean-native --parallel 4
python run_tests.py --lab 12
```

GoogleTest запускается в Docker; Python проверяет передачу параметров веб-формы.
Прямой запуск: `docker compose run --rm --no-deps tokenizer-tests skip_tests`.

## Построение

```powershell
New-Item -ItemType Directory -Force data/skips | Out-Null
build/boolean-native/skip_index.exe build --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --output data/skips/new_lab12 --reserve-mib 4608
build/boolean-native/skip_index.exe verify --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --skips data/skips/new_lab12
```

Выходной каталог должен быть новым; исходные файлы не изменяются.
При ошибке остаётся `INCOMPLETE`, открытие такого расширения запрещено.
Резерв свободного места — 4608 МиБ. Готовое расширение:
`data/skips/lab12_2026-11-08`.

Для списка длины P ≥ 256 шаг равен ceil(sqrt(P)); после каждого шага записываются
абсолютное значение, смещение следующего байта внутри списка и число уже
прочитанных записей. Короткие списки читаются последовательно. Четыре файла:
`skip_posting_terms.bin`, `skip_postings.bin`, `skip_position_terms.bin`,
`skip_positions.bin`. Таблицы содержат по 16 байт на термин, контрольные точки —
по 24 байта. Заголовки по 80 байт содержат версию, размеры, FNV-64 и привязку
к заголовкам сжатого индекса. Расширения для исходного и упакованного индекса
имеют разные привязки; использовать именно те пути, с которыми выполнялся build.

`verify` проверяет все контрольные суммы, непрерывность таблиц и каждую
контрольную точку против декодированного VB-потока. При поиске в память читаются
только точки запрошенных списков, не все таблицы или постинги. Полную проверку
контрольных сумм нужно выполнять отдельно после построения/копирования.

## Поиск и веб-форма

```powershell
build/boolean-native/boolean_search.exe --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --skips data/skips/lab12_2026-11-08 --stats --query '"god of war"' --limit 5
```

Без `--query` программа читает UTF-8-запросы по строкам stdin и возвращает JSONL.
Леммы: `--space lemma --dict data/lemmas/ru_en_v1/dictionary.bin`.
По умолчанию используется оптимизированное выполнение. Сравниваемые режимы:

- `--execution linear`, без `--skips`: последовательный алгоритм ЛР11.
- `--execution optimized`, без `--skips`: продвижение до целевого значения,
  упрощение `A AND NOT B` до разности списков, без физических прыжков.
- `--execution optimized --skips DIR`: те же алгоритмы с прыжками.

`--stats` добавляет число декодированных постингов и координат, прыжков,
пропущенных записей, документов обхода универсума, контрольную сумму всех ID
выдачи в порядке перечисления. Это счётчики логической работы, не физических I/O.

```powershell
python serve_search.py --index data/compact/lab11_vb_packed_2026-11-08/index --positions data/compact/lab11_vb_packed_2026-11-08/positions --compact data/compact/lab11_vb_packed_2026-11-08/compact --skips data/skips/lab12_2026-11-08 --dict data/lemmas/ru_en_v1/dictionary.bin
```

Открыть <http://127.0.0.1:8080/>. Интерфейс использует то же C++-ядро.
В Docker расширение смонтировано в `/skips:ro`.

## Воспроизводимые замеры

```powershell
python run_lab12.py --packed data/compact/lab11_vb_packed_2026-11-08 --skips data/skips/lab12_2026-11-08 --dict data/lemmas/ru_en_v1/dictionary.bin
```

Скрипт сначала проверяет каждую точку, затем сравнивает 13 запросов в обоих
пространствах и трёх режимах. Семь раундов: в каждом новый процесс для режима,
один прогревочный пакет и один измеряемый. Порядок режимов циклически меняется,
порядок запросов разворачивается через раунд. Кэш ОС не очищается; это не
проверка холодного чтения. Для построения с нуля указать новый `--skips DIR`
и добавить `--build`. Программа сохраняет JSONL каждого раунда, SHA-256 бинарников,
словаря и расширения, сводку, таблицы отчёта в `doc/lab12/`.

Замеры включают разбор запроса, загрузку точек нужных терминов и перечисление
всех совпадений, исключают открытие индекса, загрузку морфологии и вывод
метаданных. Проверяются число совпадений, показанные документы и контрольная
сумма всего потока результатов. На синтетических корпусах GoogleTest сравнивает
полные векторы ID и независимые ожидаемые значения.

## Ограничения

Прыжки увеличивают индекс и могут замедлять короткие запросы из-за загрузки
указателей и переходов по файлу. Шаг sqrt(P) и порог 256 не оптимизировались
под конкретные запросы. Самостоятельный NOT и OR должны перечислить свои
результаты; гарантированного ускорения для них нет. Промежуточные результаты
булевых операций не получают собственных указателей. Внутри фраз прыжки идут
по координатам, а продвижение готовой фразы как операнда сложного выражения
пока перечисляет её документы последовательно. Ранжирование не добавлялось.
