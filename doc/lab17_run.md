# ЛР17: модульные автотесты

Цель работы — получить повторяемую проверку правил и структур поисковой
системы. Набор объединяет GoogleTest, Python unittest и интеграционные
проверки с отдельной тестовой MongoDB.

## Запуск из корня проекта

Нужны Docker Desktop и Python с зависимостями из `requirements-dev.txt`.
Виртуальное окружение `.venv` используется в остальных работах.
Команда одинакова в PowerShell и Git Bash:

```bash
python run_lab17.py
```

Скрипт использует существующий тестовый Docker-образ или собирает его,
если образа нет. Для принудительной пересборки: `python run_lab17.py --rebuild-image`.
Он поднимает отдельный временный контейнер `mongo:8.0` без постоянного тома,
дожидается готовности сервера, передаёт его адрес интеграционным тестам
и останавливает контейнер после прогона. Действующая MongoDB проекта и её
данные не используются. Затем скрипт вызывает
`python run_tests.py --lab all`. C++-часть пересобирается в контейнере,
проверки CTest запускаются по отдельности; Python unittest печатает имя
и результат каждого случая. Выходы:

- `doc/lab17/build.txt` — сборка образа или запись о повторном использовании;
- `doc/lab17/mongo.txt` — запуск и остановка тестовой MongoDB;
- `doc/lab17/tests.txt` — подробный журнал всех тестов;
- `doc/lab17/summary.json` — число проверок и контрольные суммы файлов запуска.

Для короткого прогона проверок кодирования, токенизации, URL и JSON-LD:

```bash
python run_tests.py --lab 17
```

Он запускает 3 GoogleTest и 7 Python unittest. Прямой запуск GoogleTest
после пересборки: `docker compose run --rm --no-deps tokenizer-tests unit_tests`.
Код этих проверок: `tests/cpp/unit_test_lab17.cpp` и
`tests/python/test_lab17.py`. Остальные тесты лежат рядом в `tests/`.

## Тестовый план

| Область | Ожидаемое свойство | Оракул и набор |
|---|---|---|
| Токенизация | Русский/английский UTF-8, игровые имена и версии, байтовые границы; испорченный UTF-8 отвергается | Явные эталоны и свойство сохранения токенов при объединении полей |
| Лемматизация | Формы и неоднозначность не теряются; неизвестная форма не получает выдуманную лемму | Малый независимый словарь ЛР4 |
| Индекс | Постинги уникальны и возрастают, произвольные ID и пустые документы сохраняются | Синтетические корпуса ЛР7/ЛР10, полная проверка формата |
| Булев и цитатный поиск | Приоритет операций, отрицание, порядок/соседство слов и граница полей | Таблицы истинности и независимое скользящее окно ЛР8/ЛР10 |
| Сжатие и переходы | Декодирование восстанавливает исходные ID/координаты, переходы не меняют результаты | Сопоставление исходного/сжатого режимов; независимая кодировка VB для граничных чисел и проверка усечений |
| TF-IDF | Оценки, нормировка и top-k совпадают с независимой формулой и полной сортировкой | Численный эталон ЛР13 |
| Фильтры выдачи | Сайт, тип и год применяются до top-k; неизвестная дата не заменяется годом загрузки | Синтетический индекс, каталог метаданных и HTTP-тест формы |
| Робот и метаданные | URL-категория отсекается без потери статьи, значимые query-параметры сохраняются, JSON-LD находится среди шума | Табличные Python-тесты и интеграционные проверки с тестовой MongoDB |
| Интерфейс и ошибки | CLI читает UTF-8, ошибки не портят следующий запрос, веб-форма безопасно отображает результаты | Процессные CTest и Python unittest ЛР8/ЛР10/ЛР13 |

Тесты с маленькими входами изолируют конкретное правило и дают точный
ожидаемый ответ. Для некоторых модулей также проверяется взаимодействие
через CLI на синтетическом корпусе. Общая регрессия проверяет совместную
работу компонентов.

## Границы проверки

Полный корпус не нужен для модульных тестов. Интеграционные тесты работают
только со своими временными базами в отдельной MongoDB.
