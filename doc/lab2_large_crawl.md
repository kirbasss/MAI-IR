# Подготовка к большой обкачке

Полный инвентарь `data/discovery/inventory_all/url_inventory.tsv` содержит
1 055 674 URL восьми сайтов. Его импорт в MongoDB сам по себе создаст более
миллиона записей очереди, даже если `max_documents` ограничивает число
скачиваний. Поэтому сначала используем выборку и проверяем фактический расход
места и долю пригодных страниц.

## Место для MongoDB

На 6 октября 2026 года на `C:` было свободно около 7,8 ГБ, на `D:` — около
28 ГБ. Пробные 24 документа занимают в MongoDB примерно 6 МБ физического
хранилища и содержат 9,44 МБ HTML в UTF-8. Если механически экстраполировать
этот небольшой образец, 30 тысяч документов потребуют порядка 7–12 ГБ, а
миллион — сотни гигабайт. Это **не прогноз**: размер HTML и степень сжатия
различаются между сайтами. Для миллиона документов диска `D:` тоже не хватит.

MongoDB использует именованный том Docker. Чтобы перенести его вместе с
данными, в Docker Desktop откройте **Settings → Resources → Advanced → Disk
image location**, выберите новую пустую папку на `D:` и примените изменение.
Это перемещает весь дисковый образ Docker Desktop, включая остальные образы и
тома ([документация Docker Desktop](https://docs.docker.com/desktop/features/wsl/)).
Не переносите файл образа вручную и не выполняйте
`docker compose down -v`: последний вариант удаляет именованный том. Перед переносом остановите
MongoDB:

```text
docker compose stop mongo
```

После перезапуска Docker Desktop проверьте, что сохранённые документы на месте:

```text
docker compose up -d
python crawler_status.py crawler.example.yaml
```

До начала новых загрузок ожидаются `documents: 24` и `queued_urls: 24`. На
этой машине также создана резервная копия базы
`D:\MAI-IR-backups\mai_ir_before_move_2026-10-06.archive.gz`. Если после
переноса статистика показывает пустую базу, **не начинайте обкачку**: сначала
проверьте, какой том подключён, и восстановите резервную копию.

## Пробный пакет

Команда ниже делает воспроизводимую случайную выборку по 100 URL с каждого
из восьми сайтов. Она читает большой TSV построчно, хранит в памяти лишь
выбранные строки и записывает результат в `data/` (не добавляется в Git):

```text
python main.py sample-inventory data/discovery/inventory_all/url_inventory.tsv data/discovery/inventory_batch/url_inventory.tsv --per-source 100 --seed 42
python crawler.py crawler.batch.yaml
python crawler_status.py crawler.batch.yaml
```

`crawler.batch.yaml` скачивает не больше 250 URL за один запуск, выдерживает
минимум три секунды между запросами к одному хосту и не запускает параллельные
потоки. Его можно запускать снова: уже сохранённые документы не дублируются.
После HTTP 429, 403, 503 или антибот-заглушки пауза для соответствующего сайта
сохраняется в базе и действует после перезапуска; другие сайты продолжают
обрабатываться.
Смотреть следует на число `documents`, состояния очереди (`done`, `retry`,
`blocked`, `gone`) и фактический размер `storage_mib`. Запрещённые в
`robots.txt` и удалённые URL не скачиваются повторно каждый час, а
перепроверяются раз в `revisit_seconds`. Проверяйте
свободное место на диске после каждого пакета.

## Переход к 30 тысячам документов

Когда пробный пакет покажет приемлемые долю ошибок и размер одного документа,
расширьте выборку примерно до 40 тысяч URL — по 5000 с каждого сайта:

```text
python main.py sample-inventory data/discovery/inventory_all/url_inventory.tsv data/discovery/inventory_batch/url_inventory.tsv --per-source 5000 --seed 42
python crawler.py crawler.large.yaml
```

`crawler.large.yaml` ограничивает запуск 30 тысячами попыток. Это не
гарантирует 30 тысяч пригодных документов: ошибки, запрещённые и удалённые
страницы уменьшают результат. Робота можно остановить `Ctrl+C` и запустить
снова с тем же YAML: незавершённый URL вернётся в очередь. Не запускайте два
экземпляра одновременно с одной базой.

После достижения этой вехи можно увеличивать инвентарь до полного миллиона,
но сначала понадобится диск существенно большего объёма. На этой машине
полную обкачку пока **не запускать**.
