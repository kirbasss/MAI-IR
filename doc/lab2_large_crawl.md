# Подготовка к большой обкачке

Полный инвентарь `data/discovery/inventory_all/url_inventory.tsv` содержит
1 055 674 URL восьми сайтов. Из них 13 211 URL распознаны как известные
страницы-каталоги и не попадут в очередь; остаётся 1 042 463 кандидата.
Это исходная оценка по сохранённому снимку; при обновлении карт число меняется.
Инвентарь теперь создаёт и пополняет сам робот, а рабочая
очередь и состояния загрузки хранятся в коллекции MongoDB `frontier`.
`crawler.large.yaml` уже указывает на этот полный файл. В начале обычного запуска
краулер обновит sitemap восьми сайтов и добавит в MongoDB отсутствующие адреса
(в том числе при первом запуске без готового TSV), хотя `max_documents: 30000`
ограничивает число обработанных URL за один запуск.

## Диск и контрольный пакет

Именованный том MongoDB находится внутри дискового образа Docker Desktop,
который на этой машине уже размещён на `D:`. Файлы `data/discovery` находятся
в проекте на `C:`. Даже выборка из 124 страниц не позволяет надёжно предсказать
расход места на миллион HTML-документов; свободного места на `D:` для полной
обкачки сейчас недостаточно. Не используйте `docker compose down -v`: команда
удалит том с базой.

Для проверки скорости, доли ошибок и объёма сначала используйте пакет из
100 URL на каждый сайт:

```powershell
python main.py sample-inventory data/discovery/inventory_all/url_inventory.tsv data/discovery/inventory_batch/url_inventory.tsv --per-source 100 --seed 42
python crawler.py crawler.batch.yaml
python crawler_status.py crawler.batch.yaml
```

`crawler.batch.yaml` отключает обновление sitemap, чтобы сохранить фиксированную
выборку, и ограничивает запуск 250 обработанными URL. Однако очередь общая для
всех конфигураций с тем же `db.name`: если полный инвентарь уже импортирован,
batch не ограничит её выбранными 800 URL. Для изолированного опыта задайте
отдельную базу, например `mai_ir_sample`. Повторный
запуск продолжает очередь новых URL: уже сохранённые документы не
перекачиваются. Паузы
после HTTP 429, 403, 503 и антибот-заглушек сохраняются отдельно для каждого
сайта. В статусе следите за `indexable_documents`, `title_only_documents`,
`excluded_documents`, `raw_pages`, `states` и `storage_mib`, а также
за свободным местом на `D:`.

Известные URL страниц-каталогов отфильтровываются при новом discovery,
объединении инвентарей, выборке и импорте в очередь. Старые записи можно
безопасно переклассифицировать из сохранённого HTML командой
`python repair_saved_documents.py crawler.batch.yaml` (предпросмотр),
затем с `--apply` при остановленном краулере. Сырые страницы не удаляются.

## Полный инвентарь и контролируемый запуск

Когда будете готовы обновить карты и добавить **все** URL в очередь,
но ещё не скачивать HTML-публикации:

```powershell
python crawler.py --seed-only crawler.large.yaml
python crawler_status.py crawler.large.yaml
```

Затем запускайте обкачку контролируемыми партиями:

```powershell
python crawler.py crawler.large.yaml
python crawler_status.py crawler.large.yaml
```

Этот запуск может обработать до 30 тысяч URL, но не гарантирует 30 тысяч
пригодных документов: часть адресов окажется удалённой, запрещённой или
недоступной. Остановить его можно `Ctrl+C`; следующий запуск продолжит работу.
Не запускайте два экземпляра `crawler.py` одновременно с одной базой.
Перед каждым следующим пакетом проверяйте свободное место на `D:`.

Уже обработанные страницы проверяются отдельной командой, когда пройдёт
`logic.revisit_seconds` после их последней проверки:

```powershell
python revisit.py crawler.batch.yaml
python crawler_status.py crawler.batch.yaml
```

Это не добавляет URL из TSV. Статус `revisit_due_now` показывает число
доступных повторных проверок. Команда соблюдает те же ограничения по
`max_documents`, `robots.txt` и задержке запросов. Не запускайте её
одновременно с `crawler.py` или другим `revisit.py` для той же базы.

Если пока рано добавлять весь миллион URL в базу, оставьте
`crawler.large.yaml` в покое и продолжайте использовать `crawler.batch.yaml`.

## Обновление sitemap и очереди

Отдельно запускать discovery больше не требуется. Обычная команда
`python crawler.py crawler.large.yaml` выполняет весь цикл:
`robots.txt → sitemap → inventory → frontier → HTML и разбор`.
Перечень сайтов задаётся в `logic.sitemap_sources`; кеш карт хранится под
`logic.discovery_data_dir`. Корневые индексы проверяются по сети каждый цикл,
дочерние карты повторно скачиваются только при необходимости. Новый `lastmod`
запрашивается сразу; неизменный известный `lastmod` перепроверяется по HTTP
не реже `sitemap_recheck_seconds` (сутки). Без `lastmod` действует короткий
`sitemap_cache_ttl_seconds` (час). Ответы 304 используют кешированное тело.
Это особенно важно для сотен архивных карт PC Gamer. При TTL=0 каждый дочерний
sitemap снова требует сетевой проверки, хотя условные HTTP-заголовки сохраняются.
В непрерывном режиме (`run_forever: true`)
обновление повторяется через `sitemap_refresh_interval_seconds` (по умолчанию
сутки) после окончания предыдущего цикла, в том числе при пустой очереди.
При полном или частичном сбое следующая попытка назначается не позже, чем
через `retry_seconds`. Новый запуск всегда начинает с актуализации карт.

Старые состояния `frontier` сохраняются; `max_documents` ограничивает только
число обработанных заданий, а не число URL в очереди. Отсутствие URL в свежем
sitemap не означает, что страница удалена: робот оставляет старый адрес.

Для ручного обновления только карт и очереди можно по-прежнему использовать
команду ниже. HTML-публикации она **не скачивает**:

```powershell
python refresh_inventory.py crawler.large.yaml
```

Можно обновить один или несколько сайтов: `--sources stopgame gamemag`.
Флаг `--force` требует HTTP-проверку всех выбранных карт без ожидания TTL
(но сохраняет условные заголовки и соблюдает robots/задержки). Изменённые
дочерние карты и новые карты не откладываются по TTL, если индекс даёт `lastmod`.
Без флага используются сайты из YAML. Ключ `--delay 1` переопределяет локальную
паузу по умолчанию, но не отменяет явные задержки сайтов и ограничения robots.
Глобальная и локальная задержки задаются в том же YAML, что и для загрузки
публикаций; также учитывается `Crawl-delay` из robots (подробности в
`doc/lab2_run.md`). Если один сайт вернёт
ошибку либо пустой инвентарь, его старые URL сохранятся, а успешно обновлённые
сайты всё равно пополнят очередь. Если не обновился ни один сайт, общий TSV
не меняется. Старые URL сохраняются и тогда, когда сайт исключил их из новой
sitemap. При частичном успехе команда сообщает об ошибках и возвращает код 1.
Она не сбрасывает состояние текущей загрузки `in_progress`.

Итог каждого цикла доступен в `crawler_meta` (`_id: "sitemap_refresh"`) и в
`python crawler_status.py crawler.large.yaml`: статус, новые адреса, ошибки
и запланированная следующая проверка. Для непрерывного режима внешний
планировщик не нужен; Docker Desktop и MongoDB должны быть запущены.

## Исправление ссылок StopGame из sitemap

Сохранённые sitemap StopGame дают новости в виде `/news/<id>/...`, тогда как
страницы публикаций открываются по `/newsdata/<id>/...`. Программа discovery и
импортёр очереди преобразуют такие URL перед сохранением. Ранее созданные
инвентари и 57 заданий очереди уже исправлены командой:

```powershell
python repair_stopgame_news.py crawler.large.yaml --apply
```

Без `--apply` команда только считает оставшиеся старые адреса. Исходные TSV
сохранены рядом с исправленными файлами с суффиксом
`.before_stopgame_news_repair.bak`, а прежние записи `frontier` — в коллекции
`frontier_url_repairs`. Статус старой ошибки HTTP 404 не переносится на новый
адрес: исправленные задания ожидают первой загрузки. Это исправляет формат URL,
но не гарантирует, что каждая отдельная публикация ещё доступна на сайте.
