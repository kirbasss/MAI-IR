# Подготовка к большой обкачке

Полный инвентарь `data/discovery/inventory_all/url_inventory.tsv` содержит
1 055 674 URL восьми сайтов. Он остаётся входным снимком адресов, а рабочая
очередь и состояния загрузки хранятся в коллекции MongoDB `frontier`.
`crawler.large.yaml` уже указывает на этот полный файл. При **первом** запуске
краулер добавит в MongoDB весь миллион URL, хотя `max_documents: 30000`
ограничивает число обработанных URL за один запуск.

## Диск и контрольный пакет

Именованный том MongoDB находится внутри дискового образа Docker Desktop,
который на этой машине уже размещён на `D:`. Файлы `data/discovery` находятся
в проекте на `C:`. Даже выборка из 124 страниц не позволяет надёжно предсказать
расход места на миллион HTML-документов; свободного места на `D:` для полной
обкачки сейчас недостаточно. Не используйте `docker compose down -v`: команда
удалит том с базой.

Для проверки скорости, доли ошибок и объёма сначала используйте пакет из
100 URL на каждый сайт:

```powershell
python main.py sample-inventory data/discovery/inventory_all/url_inventory.tsv data/discovery/inventory_batch/url_inventory.tsv --per-source 100 --seed 42
python crawler.py crawler.batch.yaml
python crawler_status.py crawler.batch.yaml
```

`crawler.batch.yaml` ограничивает запуск 250 обработанными URL. Повторный
запуск продолжает работу: уже сохранённые документы не дублируются. Паузы
после HTTP 429, 403, 503 и антибот-заглушек сохраняются отдельно для каждого
сайта. В статусе следите за `documents`, `raw_pages`, `states` и `storage_mib`, а также
за свободным местом на `D:`.

## Полный инвентарь и контролируемый запуск

Когда будете готовы добавить **все** URL в очередь, но ещё не скачивать HTML:

```powershell
python crawler.py --seed-only crawler.large.yaml
python crawler_status.py crawler.large.yaml
```

Затем запускайте обкачку контролируемыми партиями:

```powershell
python crawler.py crawler.large.yaml
python crawler_status.py crawler.large.yaml
```

Этот запуск может обработать до 30 тысяч URL, но не гарантирует 30 тысяч
пригодных документов: часть адресов окажется удалённой, запрещённой или
недоступной. Остановить его можно `Ctrl+C`; следующий запуск продолжит работу.
Не запускайте два экземпляра `crawler.py` одновременно с одной базой.
Перед каждым следующим пакетом проверяйте свободное место на `D:`.

Если пока рано добавлять весь миллион URL в базу, оставьте
`crawler.large.yaml` в покое и продолжайте использовать `crawler.batch.yaml`.

## Обновление sitemap и очереди

Команда ниже скачивает актуальные robots.txt и sitemap восьми сайтов,
объединяет новые URL со старым инвентарём и добавляет только отсутствующие
URL в MongoDB. HTML-страницы она **не скачивает**:

```powershell
python refresh_inventory.py crawler.large.yaml
```

Можно обновить один или несколько сайтов: `--sources stopgame gamemag`.
Ключ `--delay 1` задаёт паузу между запросами sitemap. Если один сайт вернёт
ошибку либо пустой инвентарь, его старые URL сохранятся, а успешно обновлённые
сайты всё равно пополнят очередь. Если не обновился ни один сайт, общий TSV
не меняется. Старые URL сохраняются и тогда, когда сайт исключил их из новой
sitemap. При частичном успехе команда сообщает об ошибках и возвращает код 1.
Она не сбрасывает состояние текущей загрузки `in_progress`.

Для периодического обновления можно создать задачу в Планировщике заданий
Windows, например раз в неделю. Укажите абсолютный путь к
`.venv\Scripts\python.exe` как программу, аргументы
`refresh_inventory.py crawler.large.yaml`, а корень проекта — в поле
«Рабочая папка» / «Start in». Docker Desktop и MongoDB должны быть запущены
к моменту выполнения задачи. При ошибке команда завершится с ненулевым кодом;
проверьте её вывод и повторите позже. Задача в системе автоматически не
создаётся.

## Исправление ссылок StopGame из sitemap

Сохранённые sitemap StopGame дают новости в виде `/news/<id>/...`, тогда как
страницы публикаций открываются по `/newsdata/<id>/...`. Программа discovery и
импортёр очереди преобразуют такие URL перед сохранением. Ранее созданные
инвентари и 57 заданий очереди уже исправлены командой:

```powershell
python repair_stopgame_news.py crawler.large.yaml --apply
```

Без `--apply` команда только считает оставшиеся старые адреса. Исходные TSV
сохранены рядом с исправленными файлами с суффиксом
`.before_stopgame_news_repair.bak`, а прежние записи `frontier` — в коллекции
`frontier_url_repairs`. Статус старой ошибки HTTP 404 не переносится на новый
адрес: исправленные задания ожидают первой загрузки. Это исправляет формат URL,
но не гарантирует, что каждая отдельная публикация ещё доступна на сайте.
