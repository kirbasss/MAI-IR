\section{Постановка задачи}

Для корпуса игровых публикаций требуется написать поисковый робот. Единственным
аргументом при запуске должен быть путь к YAML-файлу с секциями \code{db} и
\code{logic}. Робот должен сохранять в базе нормализованный URL, сырой HTML,
название источника и время загрузки в формате Unix timestamp. После остановки
обход должен продолжаться с незавершённого документа. Уже загруженные
материалы требуется периодически проверять и заменять в базе только при
изменении содержимого.

\section{Метод решения}

\subsection{Источники и входные данные}

Входом служит UTF-8 TSV-файл: короткий \code{urls.txt} из первой лабораторной
или объединённый инвентарь sitemap. Последний содержит 1\,055\,674
URL-кандидата из восьми игровых сайтов. Файл читается построчно, импортируется
в MongoDB партиями и не загружается целиком в память. URL нормализуется с
удалением параметров отслеживания; его хост сверяется с разрешённым списком
для соответствующего источника.
Для пробного обхода используется воспроизводимая выборка URL по сайтам;
порядок очереди перемешивается устойчивым хешем.

\subsection{Очередь и сохранение документов}

В коллекции \code{frontier} у каждого URL есть состояние, время следующей
попытки, число попыток и служебные HTTP-заголовки. Для URL создаётся запись
\code{documents} с полями \code{url}, \code{source}, \code{html},
\code{fetched_at} и \code{content_sha256}; также сохраняются результат
парсера и HTTP-метаданные. Ключ \code{_id} равен нормализованному URL,
поэтому повторная загрузка не создаёт дубликатов.

Робот атомарно выбирает доступный URL и отмечает его как обрабатываемый.
Затем он проверяет \code{robots.txt} и делает запрос с паузой для каждого
хоста. Редиректы проверяются по отдельности: переход за пределы источника
не выполняется. После сохранения HTML URL помечается как завершённый.
При перезапуске незавершённые URL возвращаются в начало очереди. Механизм
рассчитан на один процесс робота.

\subsection{Проверка изменений}

При повторном запросе робот использует сохранённые \code{ETag} и
\code{Last-Modified}. Ответ \code{304} оставляет HTML неизменным. Если сервер
возвращает \code{200}, вычисляется SHA-256 исходного ответа: при совпадении
хеша документ также не перезаписывается. Для изменённого ответа обновляются
HTML, разбор и \code{fetched_at}. Время каждой проверки отдельно хранится в
\code{frontier.last_checked_at}. При ошибках попытка откладывается:
\code{404}/\code{410} и запрет \code{robots.txt} проверяются реже, для
\code{429} учитывается \code{Retry-After}. Пауза одного источника хранится
в MongoDB и не останавливает другие сайты.

\subsection{Журнал выполнения и план тестирования}

При переносе компонентов из \code{lab1} в \code{lab2} добавлены парсеры
GameMAG, GamingOnLinux, PC Gamer и Eurogamer. Для нового робота написаны
отдельные тесты с имитацией MongoDB и HTTP-ответов. Проверяются:

\begin{itemize}
  \item чтение YAML и оба формата входного TSV;
  \item загрузка и сохранение обязательных полей;
  \item повторный запуск после завершения и после остановки на URL;
  \item ответы \code{304}, неизменённый \code{200} и изменённый \code{200};
  \item запрет \code{robots.txt}, отличение текстовых правил от HTML-заглушки
  и отложенная попытка после \code{429};
  \item пауза для одного источника без остановки других сайтов и
  воспроизводимость выборки URL.
\end{itemize}

\section{Результаты}

Код робота запускается командой \code{python crawler.py crawler.example.yaml}.
В примере ограничение \code{max_documents: 10} позволяет проверить небольшую
часть списка \code{urls.txt}. Команда \code{python run_tests.py} проверяет
систему без сервера MongoDB и без обращений к сайтам.

Все 30 тестов прошли, из них 14 проверяют робота. Сценарии охватывают
сохранение HTML и времени Unix, продолжение после остановки, ответы
\code{304} и \code{200}, контрольную сумму, \code{robots.txt} и
\code{Retry-After}. Локальные HTML-образцы первой работы проверяются
прежними тестами.

Пробный запуск с MongoDB в Docker Compose сохранил все 24 документа восьми
источников: 9{,}44~МБ HTML и 200,556 символов извлечённого текста. Пустых
текстов и ошибок парсера нет. Пять URL StopGame сначала были отложены из-за
слова \code{captcha} в правиле \code{Clean-param} файла \code{robots.txt};
после исправления все они сохранены. Число URL из sitemap остаётся оценкой
возможного объёма корпуса, а не числом уже загруженных документов. Инструкция
по запуску приведена в \code{doc/lab2_run.md}.
Исходный код размещён в ветке \code{lab2} репозитория:
\url{https://github.com/kirbasss/MAI-IR/tree/lab2}.

\section{Вывод}

В этой работе я дополнил сбор игровых публикаций устойчивой очередью в MongoDB.
Теперь робот может продолжить обход после остановки и периодически проверять
уже сохранённые страницы. Было полезно разобраться, как связать состояние
очереди с сохранением документа и зачем при повторной проверке нужны
\code{ETag}, \code{Last-Modified} и контрольная сумма ответа.

Я проверил робота тестами и пробной загрузкой в MongoDB. При массовой обкачке
ещё нужно будет следить за ошибками сайтов и долей пригодных публикаций:
sitemap даёт лишь предварительный список адресов.
