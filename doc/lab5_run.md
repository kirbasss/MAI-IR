# ЛР5: закон Ципфа

Требование — раздел «Закон Ципфа» в `homework_3.md`: частотный график
в логарифмической шкале, теоретическая кривая и объяснение расхождений.
Частота здесь — **число вхождений токена** во всём выбранном тексте,
а не число документов, в которых он встретился.

## Метод

1. Из `documents` экспортируются заголовки и готовые тексты. HTML и диск E
   не требуются. Пустые/ошибочные и явно неиндексируемые записи отбрасываются
   теми же правилами, что в ЛР3.
2. C++ вызывает токенизатор `gaming-v3`; стоп-слова, числа, словоформы и игровые
   названия сохраняются. В базовом варианте лемматизация не применяется.
   С параметром `--dict` выполняется отдельный подсчёт после однозначной
   лемматизации. По умолчанию считаются
   заголовок и основной текст, их можно выбрать через `--field`.
3. Собственная хеш-таблица считает пары `(группа, токен)` в заданном буфере.
   При заполнении данные сортируются собственной пирамидальной сортировкой
   и сбрасываются на диск. Многопроходное слияние собственной двоичной кучей
   открывает не более 24 входных файлов и объединяет одинаковые ключи.
4. Второй внешний проход сортирует по группе, убыванию частоты и UTF-8
   написанию токена при равенстве частот. Ранги начинаются с 1, без общих рангов
   для одинаковой частоты. Частоты и модели вычисляет C++, Python только
   экспортирует данные, выбирает точки для отрисовки и строит рисунки.

В C++ нет контейнеров STL, `std::sort`, готовых счётчиков или хеш-таблиц.
На границе с разрешённым токенизатором используется его `string_view`.
Основные файлы: `cpp/zipf.cpp`, `cpp/zipf.hpp`, `cpp/zipf_main.cpp`.
GoogleTest: `tests/cpp/zipf_test_lab5.cpp`.

Теоретическая модель: `f(r) = C/r`, где `C = N/H_V`,
`H_V = 1 + 1/2 + ... + 1/V`, `N` — число вхождений, `V` — размер словаря.
Так сумма теоретических частот на рангах 1..V равна N. Это нормировка,
а не обещание совпадения с самым частым словом.

Дополнительно C++ подбирает модель `C/r^alpha` методом наименьших квадратов
в натуральных логарифмах на рангах 10..10000, ограниченных размером группы.
Выводятся alpha, C и R² в log-координатах. При недостатке точек — JSON null.
Это оценка наклона на фиксированном интервале, а не доказательство,
что всё распределение подчиняется степенному закону. Мандельброт с добавочным
сдвигом ранга пока не реализован: это необязательная часть задания.

## Группы

- `all` — весь корпус;
- `source:...` — каждый сайт;
- `language:ru`, `language:en` — язык **источника**, не автоматическое
  определение языка каждой статьи или каждого слова;
- `type:news`, `type:article`, `type:review`, `type:blog`, `type:unknown` —
  категории, если они присутствуют в снимке.

Категории не выводятся из слов текста: используются `parsed.category`
из MongoDB и отдельный `groups.tsv` с возрастающими ID документов.
Неподдержанная/отсутствующая категория превращается в `unknown`.
Заголовочные публикации и `media_only` не удаляются; короткие записи могут
влиять на сравнение типов. Одна статья участвует в нескольких независимых
разрезах: суммировать токены **между разрезами** нельзя.

В сравнении сайтов/типов/языков используется относительная частота `f/N`
внутри группы. Иначе размер сайта определял бы высоту линии.
Длины редких хвостов остаются зависимыми от объёма данных даже после нормировки.

## Сборка и прямые GoogleTest

В PowerShell:

```powershell
docker compose run --rm --no-deps tokenizer-tests
docker compose run --rm --no-deps tokenizer-tests zipf_tests --gtest_color=yes
```

Первая команда пересобирает и проверяет все C++ цели. Вторая запускает
только уже собранные GoogleTest ЛР5. Обе работают и в Git Bash.
Автотесты не требуют MongoDB, сети и полного корпуса.

Группа CTest ЛР5, включая проверку запуска CLI:

```bash
python run_tests.py --lab 5
```

Для нативной утилиты Windows:

```powershell
cmake -S . -B build/zipf-native -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_DEMO=OFF
cmake --build build/zipf-native --target zipf --parallel 2
```

## Полный эксперимент

Нужны работающая MongoDB и Python-зависимости из `requirements-lab3.txt`.
`--output` должен быть **новым каталогом**, а исполняемый файл предварительно
собран. Робот не запускается, коллекции не изменяются.

```powershell
python run_lab5.py --config crawler.large.yaml --output data/zipf/run_001 --report-dir doc/lab5
```

Из уже готового снимка (MongoDB не нужна):

```powershell
python run_lab5.py --snapshot data/zipf/run_001/snapshot --output data/zipf/run_002
```

Контрольные суммы корпуса и классификации проверяются до подсчёта;
в результатах сохраняется SHA-256 бинарника и полной таблицы частот.
Старые снимки ЛР3–ЛР4 остаются читаемыми, но обычно не содержат категорий:
в таком случае разрез типов помечается недоступным, а не подставляется.
Обычный курсор экспорта не создаёт транзакционный снимок MongoDB, зато
все повторы используют один завершённый и проверенный локальный файл.

Прямой запуск C++ без Python, из PowerShell:

```powershell
build/zipf-native/zipf.exe --corpus data/zipf/run_001/snapshot/corpus.bin --groups data/zipf/run_001/snapshot/groups.tsv --output data/zipf/counts_001 --memory-mib 64
```

Для `--output` C++ требуется новый каталог с уже существующей родительской
папкой. `--field title|text|both`, `--fit-min`, `--fit-max` доступны в `--help`.
Если `groups.tsv` отсутствует, не передавайте `--groups`.

## Результаты и ограничения

В локальном каталоге запуска:

- `snapshot/` — корпус и метаданные (если выполнялся экспорт);
- `counted/frequencies.tsv` — все ранги, токены, частоты и доли по группам;
- `counted/statistics.json` — N, V, hapax (слова с одним вхождением),
  нормировка Ципфа, alpha и R²;
- `summary.json`, `curves.tsv`, `README.md` — компактные результаты;
- `zipf_all`, `zipf_source`, `zipf_language`, `zipf_type`, `top_terms`
  в PNG и PDF — рисунки;
- `counter.log` — вывод C++.

В `--report-dir` копируются только компактные данные и рисунки.
Корпус и полные частоты остаются в игнорируемом `data/`.
Рисунки используют логарифмическую выборку точек, а не миллионы маркеров;
сами счётчики и модели рассчитаны по полным данным.

На ошибке сохраняется `INCOMPLETE`: эти результаты использовать нельзя.
Чужие и существующие файлы не перезаписываются. Успешное завершение удаляет
собственные временные части. После прерывания создавайте новый каталог;
автоматического продолжения нет. Временные файлы требуют места на диске.
`--memory-mib` ограничивает буфер счётчика, а не RSS всего процесса:
дополнительно нужны текущее поле (до 64 МиБ), токенизатор, записи слияния
и небольшие списки временных файлов. Не весь корпус и не весь словарь
обязаны помещаться в оперативной памяти.

Кривая реального корпуса отклоняется от прямой из-за конечного словаря,
ступенчатого редкого хвоста, смеси языков, игровой тематики, собственных имён,
словоформ и неодинаковой длины публикаций. Ошибки парсинга и дубли тоже
могут влиять на частоты; один график не подтверждает полноту извлечения текста.

## Сравнение с лемматизацией

«Аппроксимация» на графике — модель `C/r^alpha`, параметры которой
оцениваются **по наблюдаемым частотам** на рангах 10..10000.
Критерий — сумма квадратов отклонений в логарифмах.
У теоретической кривой Ципфа показатель фиксирован: alpha=1.
Сходство с аппроксимацией не является независимой проверкой закона Ципфа.

`--dict` подключает собственный C++-лемматизатор ЛР4 и его бинарный словарь.
При единственной лемме словоформа заменяется ею. При неоднозначном разборе
и отсутствии слова в словаре исходный токен сохраняется.
Например, «игры» объединяется с «игра», а «стали» не размножается
в два вхождения «сталь» и «стать». Каждое исходное вхождение считается
ровно один раз, поэтому N сопоставим с исходным экспериментом.
Это **консервативная лемматизация**, без контекстного снятия омонимии.

Для нового запуска (каталоги должны быть новыми):

```powershell
cmake --build build/zipf-native --target zipf --parallel 2
python run_lab5.py --snapshot data/zipf/run_2026-11-07/snapshot --dict data/lemmas/ru_en_v1/dictionary.bin --output data/zipf/lemmas_002
python compare_zipf.py --surface data/zipf/experiment_2026-11-07 --lemmas data/zipf/lemmas_002 --output data/zipf/comparison_002
```

`compare_zipf.py` проверяет совпадение контрольных сумм снимка и групп,
полей, интервала регрессии, числа документов и числа токенов в каждой группе.
Он не считает частоты заново: использует фактический вывод C++.
Графики сравнения используют собственные ранги каждого распределения;
это не сравнение одних и тех же слов на одинаковых позициях.
