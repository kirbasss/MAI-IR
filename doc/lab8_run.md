# ЛР8: булев поиск

Поиск использует готовый индекс ЛР7: `data/boolean/lab7_2026-11-07/index`.
Исходные HTML, MongoDB и диск E не нужны. Индекс открывается только для чтения.
Основная логика — C++17 без STL-контейнеров; Python обслуживает HTML-форму и сохраняет замеры.

## Язык запросов

| Конструкция | Значение |
|---|---|
| `doom AND quake` | Оба слова в документе |
| `doom OR quake` | Хотя бы одно слово |
| `doom AND NOT minecraft` | Есть doom, отсутствует minecraft |
| `NOT doom` | Все документы корпуса, в которых нет doom |
| `(doom OR quake) AND bethesda` | Скобки меняют порядок вычисления |

Приоритет: `NOT`, затем `AND`, затем `OR`. Поддержаны также `!`, `&`, `|`.
Словесные операторы пишутся заглавными буквами. Между словами необходим явный оператор:
`doom quake` считается ошибкой. Кавычки и фразовый поиск пока не поддерживаются.
Каждый операнд нормализуется тем же токенизатором, что и корпус, и должен давать ровно один токен.
Слово `and` в нижнем регистре можно искать как обычный термин.

`--space surface` ищет нормализованные словоформы. `--space lemma` лемматизирует
операнды и объединяет списки всех возможных разборов. Например, запрос `стали`
ищет объединение списков `сталь` и `стать`. Отрицание применяется ко всему этому объединению.
Неизвестные словарю слова сохраняются. Словарь должен побайтово совпадать со словарём построения
индекса; это проверяется по сохранённому отпечатку FNV-64.

Результаты уникальны и упорядочены по возрастающему ID. Семантического ранжирования нет.
`total` — точное число совпадений; `--limit` ограничивает только число показанных документов.
Полный подсчёт выполняется даже при `--limit 0`.

## Сборка и GoogleTest в Docker

В Git Bash после изменения исходников:

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps tokenizer-tests sh -ec 'cmake -S /src -B /build -G Ninja -DCMAKE_BUILD_TYPE=Release && cmake --build /build --parallel 2'
docker compose run --rm --no-deps tokenizer-tests boolean_search_tests --gtest_color=yes
```

В PowerShell убрать `MSYS_NO_PATHCONV=1`. Тестовый словарь и маленькие индексы
создаются GoogleTest автоматически. Настоящий корпус для тестов не нужен.
11 GoogleTest проверяют булеву алгебру, приоритеты, 64-битные ID, пустые документы,
неоднозначные леммы, ограничения запросов, ошибки и JSON-выдачу CLI.
Один тест сравнивает 64 выражения с независимой таблицей истинности
в каждом из двух пространств: всего 128 сравнений полных списков ID.

Все проверки только ЛР8, с пересборкой C++ и тестами HTML-обвязки:

```bash
python run_tests.py --lab 8
```

## Демонстрация на настоящем индексе

Git Bash:

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps tokenizer-tests boolean_search --index /indexes/lab7_2026-11-07/index --query '(doom OR quake) AND NOT minecraft' --limit 5
MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps tokenizer-tests boolean_search --index /indexes/lab7_2026-11-07/index --space lemma --dict /lemmas/ru_en_v1/dictionary.bin --query 'games AND doom' --limit 5
```

Без `--query` программа получает по одному запросу в строке stdin и выдаёт
по одному JSON-объекту в строке stdout. Ошибка запроса возвращается как `{"error":"..."}`,
последующие строки продолжают обрабатываться. Итоговый код возврата будет ненулевым,
если хотя бы одна строка ошибочна. Ошибки запуска пишутся в stderr.
Потоки и файлы должны быть в UTF-8. В Git Bash можно подать файл:

```bash
MSYS_NO_PATHCONV=1 docker compose run --rm -T --no-deps tokenizer-tests boolean_search --index /indexes/lab7_2026-11-07/index < tests/fixtures/lab8_queries.txt > build/lab8_queries.jsonl
```

Объект результата содержит `query`, `space`, `total`, `elapsed_ms`, `results`.
В каждом документе — `id`, `title`, `url`, `source`. `elapsed_ms` измеряется C++:
нормализация, разбор выражения и получение всех ID. Загрузка индекса и словаря,
чтение метаданных и сериализация JSON в эту величину не входят.

## Нативная сборка Windows и веб-форма

```bash
cmake -S . -B build/boolean-native -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_DEMO=OFF
cmake --build build/boolean-native --target boolean_search --parallel 2
python serve_search.py --index data/boolean/lab7_2026-11-07/index --dict data/lemmas/ru_en_v1/dictionary.bin
```

Открыть <http://127.0.0.1:8080/>. Форма поддерживает оба пространства, булевы
операторы, вывод количества совпадений и первых 20 документов со ссылками.
Сервер запускается в текущем терминале, остановка — Ctrl+C.
Дополнительные Python-пакеты для формы не нужны. На Linux передать путь к нативной
сборке через `--binary`; сервер и бинарник должны работать в одной ОС.

Python передаёт строку через UTF-8 stdin непосредственно C++-процессу.
Для каждого HTTP-запроса запускается отдельный процесс, поэтому полное время
ответа формы включает загрузку морфологического словаря. Сервер обрабатывает запросы
последовательно, чтобы несколько копий словаря одновременно не занимали память.
Это интерфейс демонстрации; постоянный процесс можно добавить в дальнейшем.

## Метод и ограничения

Рекурсивный спуск строит собственное дерево выражения. Лист читает список термина
независимым курсором. Узлы выполняют потоковое пересечение, объединение и разность,
храня только текущие ID дочерних потоков. Промежуточные множества и полный результат
не материализуются в памяти. Для одиночного `NOT` множество всех документов
перечисляется через `document_at`, включая пустые документы и разрывы между ID.

Операция над двумя отсортированными потоками работает за линейное время по длине
прочитанных потоков. В текущей реализации `A AND NOT B` вычисляет также поток дополнения
`B` относительно корпуса. Поэтому запросы с отрицанием могут быть заметно медленнее
обычных пересечений. Перестройка дерева в `A \ B`, прыжки и планирование по df пока не реализованы.

Пределы: 8192 байта запроса, 64 операнда, 64 уровня вложенности, 1024 узла после
раскрытия лемм, до 1000 отображаемых документов CLI. Превышение даёт явную ошибку.
Ограничено и количество одновременно открытых списков. Позиции слов, цитатный поиск,
сниппеты и ранжирование относятся к следующим работам.

## Повторение замеров и отчёт

Выбрать новый каталог результата:

```bash
python run_lab8.py --index data/boolean/lab7_2026-11-07/index --dict data/lemmas/ru_en_v1/dictionary.bin --output data/boolean/lab8_checks
```

Скрипт запускает тесты ЛР8, затем читает `tests/fixtures/lab8_queries.txt` и выполняет
три повторения каждого запроса в одном процессе каждого режима. Сохраняются исходные
JSONL-ответы, времена каждого повторения, медианы, пиковая память процесса,
отпечатки исполняемого файла, словаря и заголовков индекса. Python не вычисляет поисковую выдачу.

Проверенный прогон: [lab8/README.md](lab8/README.md), [журнал](lab8/tests.txt).
Отчёт: [редактируемый LaTeX](report_lab8.tex), [PDF](report_lab8.pdf).
Увеличение количества совпадений после лемматизации демонстрирует изменение множества
кандидатов. Оценка релевантности требует отдельно размеченных документов и здесь не подменяется
этими числами; к ней вернёмся при подготовке отчёта по лемматизации.
