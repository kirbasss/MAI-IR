# Архивирование исходных HTML на внешний диск

MongoDB остаётся в Docker на SSD. В ней сохраняются `documents` (готовый текст
и метаданные), `frontier` (очередь), `crawler_meta` и небольшие записи `raw_pages`.
Большие HTML завершённых публикаций можно вынести пачками на внешний диск.
Это **не полный резервный снимок базы**: очередь и готовые документы нужно
резервировать отдельно.

## Одна команда для очередного переноса

Остановить робот и парсер (Ctrl+C), подключить E:, оставить MongoDB запущенной:

```bash
python archive_raw.py crawler.large.yaml --auto --maintenance-reserve-gib 4
```

Это один перенос за запуск, не фоновая служба. Команда сама:

1. Находит готовую пачку, перенос которой не завершился, и продолжает её.
   Если такой пачки нет, выбирает новую папку `raw_дата_время_идентификатор`
   внутри `E:/Kirbass/MAI-IR/raw_archives`.
2. Экспортирует только новые готовые HTML, полностью проверяет архив и
   восстановление образцов, затем заменяет HTML ссылками на E:.
3. Сохраняет прежние обработанные документы и очередь. Если подходящих новых
   HTML нет, завершает работу без создания пустой пачки.

Повторять ту же команду можно после каждой остановки робота по месту.
При продолжении уже перенесённые записи пропускаются. Один запуск обрабатывает
одну пачку: после завершения старой прерванной пачки для новых HTML запустить
команду ещё раз. Незавершённые **экспорты** с `INCOMPLETE` сохраняются и
пропускаются; исходные HTML для них не удалялись.

Каталог `E:/Kirbass/MAI-IR/raw_archives` должен уже существовать. Если диск
отключён, программа завершится с ошибкой. Другой существующий каталог можно
указать через `--archive-root E:/другой/каталог`.

`--maintenance-reserve-gib 4` явно разрешает только операции переноса работать
при остатке не менее 4 ГиБ. Это полезно, когда робот остановился у своего
порога 4,5 ГиБ. Конфиг робота не меняется; автоматического снижения порогов нет.
Без этого флага перенос требует резерв из YAML. На диске архива по-прежнему
должно оставаться не менее 5 ГиБ.

**После переноса свободное место Windows может почти не увеличиться.**
MongoDB получает внутреннее место для повторного использования, а файл Docker
остаётся прежнего размера. Если на D: по-прежнему меньше 4,5 ГиБ, обычный робот
всё ещё остановится: нужно освободить место Windows или отдельно обслужить
MongoDB/VHDX. Эта команда не сжимает образ и не запускает обкачку автоматически.

## Создать и проверить пачку

Остановить робот и обработчик парсинга, подключить E:, оставить MongoDB запущенной.
Для каждой новой пачки использовать **новый** каталог:

```powershell
python archive_raw.py crawler.large.yaml --output-dir E:/Kirbass/MAI-IR/raw_archives/raw_2026-10-24_01 --evict
```

Без `--evict` программа только создаёт и проверяет архив, не меняя рабочую базу.
Архивирование удерживает обе локальные блокировки — робота и парсера. Обход
сайтов и импорт новых адресов эта команда не запускает.

В пачку попадают только HTML с завершённым или старым состоянием разбора,
для которых существует готовый индексируемый документ той же версии
(`content_sha256`, `raw_generation`, `fetched_at`, `raw_page_id`). Задания в
работе, ожидающие разбора, ошибки и несогласованные пары остаются локально.

Последовательность:

1. Экспортировать исходные записи `raw_pages` без потери полей и типов BSON.
2. Синхронизировать файлы архива, сохранить индекс и манифест.
3. Прочитать **каждую** запись заново: проверить SHA-256 частей, индекс,
   границы записей, gzip CRC, BSON и SHA-256 HTML, итоговые счётчики.
4. Дополнительно восстановить образцы каждого сайта через временную MongoDB
   и сравнить их побайтово. Удаляется только эта автоматически созданная
   проверочная база; рабочая база не затрагивается.
5. Заменить `html` ссылкой на архив только у записей, полностью совпадающих
   с экспортированной версией. Изменённые записи пропускаются.

`documents` и `frontier` при переносе не изменяются. В `raw_pages` остаётся
метаинформация, `html_present: false`, `raw_storage: "archive"`,
`parse_state: "archived"`, а также `raw_archive` с путём, смещением и хешами.
В коллекции `raw_archives` хранится каталог пачек.

## Формат пачки

- `raw_000001.bson.gz`, … — части примерно по 128 МиБ сжатых данных.
  Каждая исходная BSON-запись сжимается отдельным gzip-потоком; части содержат
  последовательность таких потоков. Это не формат `mongodump --archive`.
- `index.sqlite` — индекс URL → часть, смещение, длина, контрольные суммы.
- `manifest.json` — версия формата, база-источник, счётчики по сайтам,
  размеры и SHA-256 частей и индекса.
- `verification.json` — результат полной проверки.
- `eviction.json` — результат замены локальных HTML ссылками.
- `INCOMPLETE` — экспорт не завершён; удалять исходные HTML по такому архиву
  программа **не разрешает**.

Чтение одной страницы не требует распаковывать всю пачку. Функция
`src.raw_archive.read_archived_raw(stub)` читает только указанный gzip-поток
и проверяет хеши. Архивы не содержат кода парсера: для повторного разбора
используется текущий код проекта.

## Если процесс прервался

При незавершённом экспорте рабочие HTML ещё не удалялись. Не удалять ничего
из MongoDB вручную. Оставить неполный каталог для диагностики и начать
новый экспорт в **другой** каталог.

Готовую пачку можно отдельно полностью проверить:

```powershell
python archive_raw.py crawler.large.yaml --output-dir E:/Kirbass/MAI-IR/raw_archives/raw_2026-10-24_01 --existing
```

Если прервалась замена HTML ссылками, продолжить той же пачкой:

```powershell
python archive_raw.py crawler.large.yaml --output-dir E:/Kirbass/MAI-IR/raw_archives/raw_2026-10-24_01 --existing --evict
```

Перед продолжением архив снова проверяется полностью. Уже архивированные
записи не изменяются; новые версии HTML не удаляются.

### Отдельный резерв для обслуживания

Экспорт читает MongoDB и пишет архив на E:, поэтому ему не требуется снижать
порог обкачки. Для последующей замены HTML ссылками нужны небольшие служебные
записи в MongoDB. Если на D: осталось чуть меньше порога робота, можно **явно**
разрешить только этой операции отдельный резерв, например 4 ГиБ:

```powershell
python archive_raw.py crawler.large.yaml --output-dir E:/Kirbass/MAI-IR/raw_archives/raw_2026-10-26_01 --existing --evict --maintenance-reserve-gib 4
```

Флаг действует с `--evict` или `--auto`, не меняет YAML и не отключает проверки
доступности дисков/MongoDB. При достижении уже этого резерва замена останавливается;
после освобождения места её можно продолжить той же командой. Резерв E: остаётся
5 ГиБ. Проверка всего архива и восстановления образцов по-прежнему обязательна.
Указывать сниженный резерв следует осознанно, а не применять его для загрузки
новых HTML. Защита обычного робота и парсера остаётся на пороге из YAML
(сейчас 4,5 ГиБ в `crawler.large.yaml`).

Даже после успешной замены HTML робот может продолжать сообщать о нехватке
места: свободные страницы WiredTiger ещё не означают свободное место Windows.
Для продолжения нужно обеспечить прежний резерв на D: — освободить место или
отдельно обслужить файлы MongoDB и VHDX (см. ниже).

## Как работать дальше

Обычные команды робота и парсера остаются прежними. При новой версии страницы
робот сохраняет свежий HTML в MongoDB и ставит его на разбор. Старая версия
остаётся в архиве. HTTP 304 или HTTP 200 с прежним хешем не требуют
подключённого E:, если готовый документ согласован с архивной записью.

Для явного повторного разбора всех сохранённых HTML подключить E:

```powershell
python parse_worker.py crawler.large.yaml --reparse
```

Обработчик читает архивный HTML напрямую, не возвращая его навсегда на SSD.
`--reparse` ставит в очередь все сохранённые страницы; `--max-documents`
ограничивает только число разборов за запуск, не размер этой очереди.
Если прервать массовый повторный разбор, оставшимся архивным заданиям
также понадобится подключённый E:.
Если диск отсутствует или запись повреждена, обработчик останавливается с
ошибкой хранилища; готовый текст не заменяется ошибкой парсинга. После
подключения диска обычный запуск восстановит незавершённое задание.

Не отключать E: во время архивирования или чтения архивов. После завершения
команды диск можно безопасно извлечь средствами Windows. Не переименовывать
каталоги пачек и не менять букву диска: абсолютный путь записан в MongoDB.
Сохранять **всю** папку пачки, а не только `.gz`; желательно иметь вторую копию
на другом носителе. Один внешний диск не защищает от его поломки.

## Освобождение места

Удаление `html` освобождает страницы внутри файлов WiredTiger для дальнейшего
использования MongoDB. Файлы коллекции и Docker VHDX обычно **не уменьшаются
сразу**, поэтому свободное место Windows может почти не измениться. MongoDB
сможет использовать освобождённое внутреннее место при дальнейшей обкачке.
Это не обещание, что VHDX больше никогда не будет расти: резерв свободного
места и защиту `disk_watch_paths` нужно сохранять.

Сжатие VHDX и `compact` не выполняются автоматически: это отдельное
обслуживание, которое нельзя делать одновременно с обкачкой без подготовки.
