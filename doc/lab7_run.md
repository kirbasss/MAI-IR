# ЛР7: булев индекс

Индекс сопоставляет нормализованному термину отсортированный список ID
документов, содержащих этот термин. Повторение слова и совпадение в заголовке
и основном тексте не дублируют ID. Частота `df` — число документов, а не
число вхождений слова (как в ЛР5).

Основной код — `cpp/boolean_index.cpp`, интерфейс чтения —
`cpp/boolean_index.hpp`. Все структуры индекса, сортировка, хеширование,
бинарный поиск и слияние реализованы самостоятельно на C++17 без STL-контейнеров.
На границе с токенизатором используются его `string_view` и callback.
Python подготавливает URL-каталог, проверяет SHA-256, запускает C++
и сохраняет измерения; частотные словари и списки ID он не строит.

## Построение

На входе — завершённый снимок `MAIIR3-v1` из ЛР3/ЛР5.
MongoDB, сеть и внешний диск E не нужны. Ветку и снимок можно использовать
без повторной выгрузки текстов.

1. Текст читается по одному полю. Токены добавляются в собственную
   хеш-таблицу пар `(пространство, термин, ID документа)`.
2. При заполнении буфера пары сортируются собственной пирамидальной
   сортировкой и сбрасываются во временную часть. Дубли внутри части исключены.
3. Части сливаются собственной двоичной кучей; одинаковые пары из разных
   частей тоже объединяются. За один проход открыто не более 24 входов.
4. Из потока уникальных пар записываются словарь и последовательные списки ID.
   Заголовки, URL и названия источников сохраняются в индекс отдельно.

Словарь располагается на диске в лексикографическом порядке. Для обращения
к списку используется бинарный поиск по фиксированным записям словаря,
а не загрузка всего словаря в RAM. Курсор списка читает ID последовательно;
разные курсоры имеют независимые файловые позиции.

### Словоформы и леммы

Без `--dict` строится только пространство `surface` — исходные
нормализованные токены. С `--dict` дополнительно строится `lemma`.
В нём сохраняются все различные словарные варианты. Неизвестные слова
остаются как есть. Исходное пространство сохраняется при любом режиме.

Например, «стали» добавляет документ к «сталь» и «стать», но в каждом
из списков ID документа встречается только один раз. Это расширяет
кандидатов для будущего поиска, не снимая омонимию. Политика отличается
от консервативной лемматизации в эксперименте Ципфа: здесь строятся списки
наличия слова, а не сопоставимые распределения числа вхождений.
`tokens` в статистике — число исходных токенов; `lemma_emissions` —
число разобранных альтернатив до исключения дублей пар.

## Сборка и тесты

Нативная Release-сборка Windows:

```powershell
cmake -S . -B build/boolean-native -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF -DBUILD_DEMO=OFF
cmake --build build/boolean-native --target boolean_index --parallel 2
```

Перед прямым запуском GoogleTest пересобрать цели в Docker:

```bash
docker compose run --rm --no-deps tokenizer-tests
docker compose run --rm --no-deps tokenizer-tests boolean_index_tests --gtest_color=yes
```

Обе команды работают в Git Bash и PowerShell. Первая также проверяет
остальные C++ работы, вторая запускает только GoogleTest ЛР7.
Отдельная группа CTest и Python-тесты подготовки каталога:

```bash
python run_tests.py --lab 7
```

GoogleTest: `tests/cpp/boolean_index_test_lab7.cpp`. Проверяются df и точные
списки ID, дубли между полями/частями, произвольные 64-битные ID,
документы только с заголовком и без токенов, разные размеры буфера,
многопроходное слияние, независимость курсоров, словарь лемм, омонимия,
чтение заголовков/URL без исходного корпуса, повреждения файлов,
незавершённые индексы и резерв диска.

## Полный запуск

```powershell
python run_lab7.py --snapshot data/zipf/run_2026-11-07/snapshot --output data/boolean/run_001 --dict data/lemmas/ru_en_v1/dictionary.bin --check-zipf doc/lab5/summary.json --report-dir doc/lab7
```

`--output` должен указывать **новый** каталог. Все большие файлы остаются
в игнорируемом `data/`; `--report-dir` получает только статистику и журналы.
`--check-zipf` проверяет, что N и словарь исходных терминов совпадают с ЛР5
на том же снимке, но не подменяет индекс таблицей частот.

Прямой запуск C++, без Python (каталог URL предварительно подготовлен
предыдущей командой; можно не передавать `--urls`, тогда URL в индексе не будет):

```powershell
build/boolean-native/boolean_index.exe build --corpus data/zipf/run_2026-11-07/snapshot/corpus.bin --urls data/boolean/run_001/urls.bin --dict data/lemmas/ru_en_v1/dictionary.bin --output data/boolean/index_002 --memory-mib 64
build/boolean-native/boolean_index.exe verify --index data/boolean/index_002
build/boolean-native/boolean_index.exe inspect --index data/boolean/index_002 --term doom --limit 10
build/boolean-native/boolean_index.exe inspect --index data/boolean/index_002 --term game --space lemma --limit 10
```

`inspect` принимает один уже нормализованный токен и показывает df
и начало списка. Это инспекция индекса, без разбора выражений AND/OR/NOT.
Разбор запросов и поисковый интерфейс — ЛР8.

## Формат индекса

Все числа записаны явно в little-endian; память C++-структур в файл
целиком не копируется. Формат `MAIIR-BOOLEAN-v1`, версия входит в сигнатуру.

| Файл | Содержимое |
|---|---|
| `terms.bin` | Фиксированные записи по 40 байт: пространство, длина и смещение термина, смещение списка, df |
| `postings.bin` | Последовательные несжатые uint64 ID, по 8 байт |
| `documents.bin` | Фиксированные записи по 64 байта: ID, ссылки на заголовок, URL и источник |
| `strings.bin` | UTF-8 строки словаря и метаданных |
| `statistics.json` | Статистика построения |

Каждый бинарный файл имеет заголовок 80 байт с размерами, контрольной
суммой FNV-1a и привязкой к корпусу, URL-каталогу, версии токенизатора
и словарю лемматизации. Для воспроизводимости обвязка дополнительно
сохраняет SHA-256 входов, бинарника и каждого файла индекса.
Это служебные проверки целостности, не криптографическая аутентификация.

`verify` читает все данные, проверяет контрольные суммы, порядок словаря,
отсутствие дублей и убывающих ID, границы списков и принадлежность ID
документному множеству. Обычное открытие проверяет заголовки/размеры,
а не перечитывает гигабайты на каждый запрос.

Интерфейс C++:

- `BooleanIndex::lookup()` — смещение и длина списка;
- `PostingCursor` — потоковое чтение ID;
- `document(id)` и `document_at(position)` — метаданные и перебор множества документов;
- `text()` — чтение соответствующих UTF-8 строк;
- `has_lemmas()` и `dictionary_hash()` — проверка режима и словаря при подключении поиска.

Объект `BooleanIndex` имеет собственные файловые позиции; для одновременных
потоков используются отдельные объекты. Курсоры независимы и сохраняют
порядок ID. Индекс после завершения предполагается неизменяемым.

## Память и место

`--memory-mib 64` ограничивает буфер пар, а не весь процесс. Дополнительно
нужны текущее поле до 64 МиБ, буферы слияния, список частей и, при `--dict`,
примерно 166,54 МБ морфологического словаря. Полный корпус и весь словарь
индекса в RAM не загружаются. Обвязка измеряет пиковый рабочий набор процесса.

Перед созданием временных частей и во время записи проверяется свободное
место. По умолчанию сохраняется резерв **4,5 ГиБ** (`--reserve-mib 4608`),
настройки робота не меняются. Если резерв достигнут, выполнение завершается
с ошибкой и маркером `INCOMPLETE`. Такой индекс не открывается читателем.
Существующие результаты и исходный корпус не перезаписываются.
При прерывании автоматического продолжения нет: нужен новый каталог;
частично созданные файлы оставляются для диагностики.

ID относятся к конкретному снимку, а не к позиции статьи в текущей MongoDB.
Стоп-слова и числовые токены сохраняются. Позиции слов, сжатие, прыжки по
индексу и ранжирование в эту работу не входят.
